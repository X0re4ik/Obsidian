## В чем отличие join от detach?

`.join()` дожидается завершение работы потока, в то время как `.detach()` отсоединяет объект `std::thread` от основного потока выполнения. После выполнения операций `.join()` и `.detach()` метод `joinable() == false`.

### Что такое mutex? Зачем он нужен? Как устроен?

`std::mutex` является одним из основных примитивов синхронизации потоков. Необходим `std::mutex`, в первую очередь, для устронение гонки данных. Верзнеуровнего `std::mutex` утроен при помощи механизмов `futex` и `CAS (Compare-And-Swap)`. Алгоритм следующий:
1) Поток пытается изменить слово состояния мьютекса с помощью атомарной инструкции (на x86 это обычно `cmpxchg`)
2) `futex` вызывается **только если** атомарная операция не смогла захватить мьютекс. Поток уходит в ядро и засыпает в ожидании `FUTEX_WAIT`

### Как правильно управлять блокировкой mutex? Что такое std::lock_guard и std::unique_lock? Чем они отличаются друг от друга?

`std::mutex` имеет методы `.lock()` и `.unlock()`, которые захватывают и освобождают мютекс, соотвественно. Но, если в промежутке между этими жвумя операциями произойдёт исключение, то мьютекс навсегда останется заблокированным. Чтобы этого избежать есть  `std::lock_guard` - это обёртка над `std::mutex`, которая придерживается идеомы `RAII`. `std::lock_guard` в своем конструкторе вызывает `.lock()`, а в деструкторе `.unlock()`. `std::unique_lock` похож на `std::lock_guard`, но может быть переиспользован, так как обладает методами `.lock()/.try_lock()` и `.unlock()`

### Что такое взаимная блокировка (deadlock)? Приведи пример ситуации, когда она может возникнуть. Как её избежать?

Взаимная блокировка - это ситуация, когда два и более потока заблокированы, потому что каждый из них ждет ресурс, занятый другим.

**Пример:**
```C++
strcut A {
	std::mutex m;
	int balance;
};

void transfer(A& to, A& from, int sum) {
	std::lock_guard alock{to.m};
	std::lock_guard block{from.m};
	
	to.balance += sum;
	from.balance -= sum;
}

// Поток 1
transfer(a, b, 100);
// Поток 2
transfer(b, a, 100);
```

В примере выше может возникнуть ситуация:
1) "Поток 1" заходит в transfer
2) "Поток 1" **захватывает** mutex объекта **a**
3) "Поток 2" заходит в transfer
4) "Поток 2" **захватывает** mutex объекта **b**

Далее ни "Поток 1" , ни "Поток 2" не могут выполняться, так как оба мьютекса a и b уже захвачены.

Единого правила по избегаю deadlock-нет, потому что они очень индивидуальны. Но можно придерживаться некоторых правил:

1) Единый порядок захвата
2) Использования `std::scoped_lock(m1, m2)` при захвате нескольких мьютексов
3) Короткие критические секции

### Что такое гонка данных (data race)? Чем она отличается от deadlock?

Гонка данных (`data race`) - это сценарий, когда несколько потоков пытаются записать данные без синхронизации своих действий. Типичный пример:
```C++
int g_counter = 0;

std::thread t1([&](){ ++g_counter; });
std::thread t2([&](){ ++g_counter; });
```

Если `deadlock` может полностью заблокировать работу прогаммы, то `data race` может привести к неопредленному поведению.

### Что произойдет, если объект std::thread будет разрушен, а поток не был ни joined, ни detached?

В деструкторе `std::thread` есть условие:
```C++
if (joinable()) std::__terminate();
```
Соотвестветсвенно, если мы не дождались `.join()` и/или не вызвали `.detached()`, то объект будет считаться `.joinable()` - программа заершится с `std::terminate`

### Модель OSI. Расскажи кратко про каждый уровень.

OSI - это концептуальная модель: делим сетевую комуникацию на 7 горизонтальных уроней, каждый решает только свою задачу и общается только с соседями сверху и снизу.

1) Физический - Самый нижний уровень. Отвечает за передачу сигналов в физической среде: по кабелям, оптоволокну, радиоволнам.
2) Канальный - Отвечает за передачу данных в пределах одной локальной сети, проверяет целостность данных, обнаруживает и исправляет ошибки.
3) Сетевой - Занимается маршрутизацией: определяет, по какому пути отправлять данные. Использует IP-адреса для поиска устройств в сети, отвечает за адресацию и доставку пакетов.
4) Транспортный - Обеспечивает передачу данных между приложениями. Разбивает большие объёмы информации на части и собирает их на стороне получателя.
5) Сеансовый - Управляет сессией связи: устанавливает, поддерживает и завершает соединение между устройствами, следит за синхронизацией передачи.
6) Представления - Преобразует данные в формат, понятный приложениям. Отвечает за сжатие, шифрование и кодирование информации. Например, превращает картинку в JPEG или текст в ASCII.
7) Прикладной - Самый верхний уровень. Взаимодействует с пользовательскими программами: браузерами, почтовыми клиентами, мессенджерами.

### Модель TCP/IP. Расскажи кратко про каждый уровень.

TCP/IP - реальная модель: именно данная модель используется в обработке данных в сети. Она имеет значительно меньше уровней (4 против 7), а также допускает прокидывание данных между пакетами.

1) Канальный уровень - Устанавливает физическое соединение между устройствами в локальной сети с помощбю радиоволн и проводов
2) Межсетевой уровень - Строит маршруты между устройствами по всему интернету - этот процесс называется маршрутизацией
3) Транспортный уровень - Передача данных по маршруту, построенному на преддыдущем уровне
4) Прикладной уровень - Настраивает связи между приложениями (связь между браузером и серверным софтом)

### Что такое сокет?

Сокет представляет из себя виртуальную конструкцию из IP-адреса и порта. Сокет можно представить как телефонную трубку (а слушающий серверный сокет - как коммутатор): разделение на клиента и сервера определяет только то, кто инициирует соединение - сам сокет двунаправленный, обе стороны могут и отправлять, и принимать данные. В ОС Linux сокет идентифицируется номером файлового дескриптора. Таким образом в рамках соединения сокет имеет свой уникальный числовой идентификатор.

### Что такое IP-адрес? Какая разница между IPv4 и IPv6?

IP-адрес - это уникальный адрес устройства в сети. С помощью IP-адреса устройства находят друг друга в сети и пересылают пакеты. IP адрес состоит из номера хоста и номера сети. На данный момент поддерживается и развивается 2 версии IP: IPv4 и IPv6

**IPv4:** 32-битное число, записывается как четыре десятичных октета 0–255 через точку (например, `234.34.87.23`). Адресное пространство всего 232≈4,32^{32} \approx 4{,}3232≈4,3 млрд адресов — оно давно исчерпано, из-за чего повсеместно применяется NAT, когда много устройств делят один публичный адрес .

**IPv6:** 128-битное число, записывается как восемь блоков по 16 бит в шестнадцатеричном виде через двоеточие, с возможностью сокращения нулей через `::` (например, `2001:db8:85a3::8a2e:370:7334`). Даёт 21282^{128}2128 адресов — NAT не нужен, каждое устройство может иметь глобальный адрес .

**Ключевые различия IPv6:** огромное адресное пространство; упрощённый заголовок фиксированной длины без контрольной суммы и без полей фрагментации (маршрутизаторы пакеты не фрагментируют — это делает отправитель через ICMPv6); нет broadcast — вместо него multicast; автоконфигурация адресов через SLAAC без DHCP; изначальная интеграция с IPsec (хотя IPsec доступен и в IPv4).

### TCP. Как происходит установление соединения? Что такое TCP handshake?

В обычном случаи стороны обмениваются тремя служебными сообщениями:
```text
SYN -> SYN + ACK -> ACK
```
handshake - процедура установления соединения. Согласовать начальную точку двух последовательнсотей. Номер увеличивается на кжадый байт.
