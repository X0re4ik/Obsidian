## В чем отличие join от detach?

`.join()` дожидается завершение работы потока, в то время как `.detach()` отсоединяет объект `std::thread` от основного потока выполнения. После выполнения операций `.join()` и `.detach()` метод `joinable() == false`.

### Что такое mutex? Зачем он нужен? Как устроен?

`std::mutex` является одним из основных примитивов синхронизации потоков. Необходим `std::mutex`, в первую очередь, для устронение гонки данных. Верзнеуровнего `std::mutex` утроен при помощи механизмов `futex` и `CAS (Compare-And-Swap)`. Алгоритм следующий:
1) Поток пытается изменить слово состояния мьютекса с помощью атомарной инструкции (на x86 это обычно `cmpxchg`)
2) `futex` вызывается **только если** атомарная операция не смогла захватить мьютекс. Поток уходит в ядро и засыпает в ожидании `FUTEX_WAIT`

### Как правильно управлять блокировкой mutex? Что такое std::lock_guard и std::unique_lock? Чем они отличаются друг от друга?

`std::mutex` имеет методы `.lock()` и `.unlock()`, которые захватывают и освобождают мютекс, соотвественно. Но, если в промежутке между этими жвумя операциями произойдёт исключение, то мьютекс навсегда останется заблокированным. Чтобы этого избежать есть  `std::lock_guard` - это обёртка над `std::mutex`, которая придерживается идеомы `RAII`. `std::lock_guard` в своем конструкторе вызывает `.lock()`, а в деструкторе `.unlock()`. `std::unique_lock` похож на `std::lock_guard`, но может быть переиспользован, так как обладает методами `.lock()/.try_lock()` и `.unlock()`

### Что такое взаимная блокировка (deadlock)? Приведи пример ситуации, когда она может возникнуть. Как её избежать?

Взаимная блокировка - это ситуация, когда два и более потока заблокированы, потому что каждый из них ждет ресурс, занятый другим.

**Пример:**
```C++
strcut A {
	std::mutex m;
	int balance;
};

void transfer(A& to, A& from, int sum) {
	std::lock_guard alock{to.m};
	std::lock_guard block{from.m};
	
	to.balance += sum;
	from.balance -= sum;
}

// Поток 1
transfer(a, b, 100);
// Поток 2
transfer(b, a, 100);
```

В примере выше может возникнуть ситуация:
1) "Поток 1" заходит в transfer
2) "Поток 1" **захватывает** mutex объекта **a**
3) "Поток 2" заходит в transfer
4) "Поток 2" **захватывает** mutex объекта **b**

Далее ни "Поток 1" , ни "Поток 2" не могут выполняться, так как оба мьютекса a и b уже захвачены.

Единого правила по избегаю deadlock-нет, потому что они очень индивидуальны. Но можно придерживаться некоторых правил:

1) Единый порядок захвата
2) Использования `std::scoped_lock(m1, m2)` при захвате нескольких мьютексов
3) Короткие критические секции

### Что такое гонка данных (data race)? Чем она отличается от deadlock?

Гонка данных (`data race`) - это сценарий, когда несколько потоков пытаются записать данные без синхронизации своих действий. Типичный пример:
```C++
int g_counter = 0;

std::thread t1([&](){ ++g_counter; });
std::thread t2([&](){ ++g_counter; });
```

Если `deadlock` может полностью заблокировать работу прогаммы, то `data race` может привести к неопредленному поведению.

### Что произойдет, если объект std::thread будет разрушен, а поток не был ни joined, ни detached?

В деструкторе `std::thread` есть условие:
```C++
if (joinable()) std::__terminate();
```
Соотвестветсвенно, если мы не дождались `.join()` и/или не вызвали `.detached()`, то объект будет считаться `.joinable()` - программа заершится с `std::terminate`

### Что такое сокет?

Существует несколько типов сокета:

* TCP - сокет - надёжная поставка данных с контрллем последовательности
* UDP - сокет - быстрая передача без гарантий поставки
* Unix - сокет - локальное взаимодействие между процессами на одной машине


Алгоритм работы с сокетами:

1) Сервер создаёт сокет и привязывает его к порту
2) Сервер переходит в режим прослушивания
3) Клиент создаёт сокет и подключается к серверу
4) Происходит обмен данными
5) Соединение закрывается
