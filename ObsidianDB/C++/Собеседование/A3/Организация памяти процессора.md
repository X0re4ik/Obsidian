Каждый процесс выполняется в совбсвенной "песочнице" (виртуальное адресное пространство), которое всегда имеет размер равный 4-ём гигабайтам. Между физической памятью и виртуальной существует прослойка в виде таблице страниц (page table)

Память процесса делится на `kernal space` и `user space`. `Kernal space` - это набор адресов, которые ядро может использовать для отображения любых физических страниц.
Страницы в `kernal space` помечены, как привилигированные и обращение к ним приводит к ошибке `page fault`

В `linux` `kernal space` присутсвует в дарсеном пространстве каждого процеса и указывает на одну и ту же область физической памяти. Именно поэтому каждому процессу доступны системные операции и прерывание.

### Виртуальная память процесса

`C++` приложение практически никогда не работает с физическими адресами и `RAM` напрямую. Например:
```C++
int x = 42;
std::cout << &x;
```
Адрес, который напишет программа - это адрес внутри **виртуальной таблице**. У каждого процесса есть своя собсвтенная карта виртуальных адресов. Поэтому 2 разные программы могут иметь одни и те же виртуальные адреса, но под ними будут скрыты разные физические адреса.

**MMU (Memory Management Unit)** - блок процессора, который отвечает за перевод виртуальных адресов в физические и проверки прав доступа. ОС не переводит каждый адрес при работе программы, а заранее создаёт таблицу страниц, к которой обращается MMU при обращениии к памяти.

**Цепочка доступа к переменной**
```text
1. Ядро ОС заранее создаёт отображения
   и настраивает page tables для процесса.

2. C++-код выполняет:
   *p = 42;

3. CPU передаёт виртуальный адрес p в MMU.

4. MMU:
   TLB hit? → быстрый физический адрес → доступ к RAM
   TLB miss? → page walk по page tables → доступ к RAM
   Нет mapping / нарушены права? → page fault → ядро ОС

5. Ядро:
   может выделить страницу и поправить tables,
   либо завершить процесс, например SIGSEGV.
```

Страницы памяти
Виртуальная память делится на блоки фиксированного размера - страницы. Одна страница - 4096 байт. Права доступа создаются для **страницы**.

Права доступа делятся на:
- `r` - read, чтение;
- `w` - write, запись;
- `x` - execute, выполнение инструкций;
- user/supervisor - доступен ли адрес коду приложения или только яд

Что такое page fault

page fault генерируется в двух ситуациях:
1) Программа оращается к странице, которая еще не отображена
2) Программа обращается к странице, у которой нет нужных прав

Преимущества работы виртуальной памяти:
1) Изоляция
Один процесс не может произвольно читать память другого
2) Защита
Код приложения не может обращаться к памти ядра
3) Удобство
Кажды йпроцесс получает свою свобсвтенную адресную карту
4) Ленивая выдача RAM
Физически страницы выделаются только при реальном использовании
5) Shared libraries
Одну и ту же библиотеку можно отображать в разных процессах
6) Защита от записи в код
Страницы кода обычно не writable

Что происходит при `new`
```C++
int* p = new int(42);
```

1) Программа просит выделение памяти у аллокатора (часто `malloc`). Аллокатор делает системный вызов `brk`  и `mmap`
2) Ядро меняет карту процесса
Ядро решает, что процесс А имеет карту виртуальной памяти с ... по ....
* Ядро создаёт или изменяет запись об отображении этой области 
* Назначает ей права доступа

Системные вызовы возвращают виртуальный адрес, но часто физически никаких изменения в `RAM` не было.

3) При выполнении `*p = 42;` CPU отдает виртуальный адрес в MMU

Вопросы для самопроверки

**Вопрос:** В `int* p` хранится виртуальный или физический адрес? Опиши путь от выполнения `*p = 42` до обращения к RAM: где участвуют MMU, таблицы страниц и ядро ОС.
**Ответ:** Переменная `p` хранит именно виртуальный адрес. Процесс выполнения операции присваивания можно представить, как следующий алгоритм:
1) Процессор сообщает, что необходимо по виртуальному адресу записать число 42
2) Процессор передаёт эту информацию в MMU
3) MMU проверяет TLB - кэш процессора (TLB кэширует целые страницы (Page Table))
4) Если в TLB этот адрес есть (попаданнеие в кэш), то MMU берет физический адрес RAM из TLB и записывает туда данные
5) Если же в TLB нет этого адреса (промах кэша), то MMU ищет данную запись в Page Table
6) MMU проверяет несколько частей: Наличие отображения страницы, разрешение доступа из user space, разрешена ли запись, 
7) Если страница отображена и права одоступа есть на запись, то MMU получает физический адрес RAM и записывает данные
8) Если же нет, то MMU генерирует исключение page fault. Управление передаётся ядру, которое принимает решение, как поступить с ошибой page fault (запросить таблице данных, пробросить ошибку в программу и т.д.)

**Вопрос:** Почему ОС не переводит адреса сама при каждом `array[i]` или `*p`? Какую роль в этом играют MMU и TLB?
**Ответ:** ОС не переводит адреса при каждом `array[i]` или `*p`, потому что таких обращений могут быть миллиарды в секунду. Если бы каждое из них требовало входа в ядро, процессор должен был бы постоянно переключаться между user mode и kernel mode, выполнять код ОС и возвращаться назад; программа стала бы очень медленной.
Ядро ОС заранее создаёт таблицы страниц: в них указано, какая виртуальная страница соответствует какой физической странице и какие у неё права. MMU аппаратно использует эти таблицы при каждом обращении к памяти: переводит виртуальный адрес в физический и проверяет права чтения, записи, выполнения и user/kernel.
TLB - это аппаратный кэш недавних переводов виртуальная страница - физическая страница вместе с правами доступа. При TLB hit MMU получает перевод очень быстро, без обхода таблиц страниц. При TLB miss MMU сама обходит page tables; если mapping найден и доступ разрешён, кэширует результат в TLB. Если отображения нет либо права нарушены, MMU генерирует page fault и только тогда подключается ядро ОС.

**Вопрос:** Что такое page fault? Приведи один пример **нормального** page fault и один пример, после которого процесс, скорее всего, получит `SIGSEGV`.
**Ответ:** page fault генерируется на этапе работы MMU, возникает он в двух ситуациях:
1) Мы запросили данные, которые еще не отображены на странице
Тогда MMU возвращает ошибку ОС, которая вправе принять решение на отображение новой страницы или же пробрасыванию ошибки в программу
2) Мы запросили данные, до которых не имеет прав доступа
Тогда программа получает `SIGSEGV`


**Вопрос:** Почему одинаковый виртуальный адрес, например `0x1000`, может быть валиден одновременно в двух разных процессах, но вести к разным данным?
**Ответ:** Потому что виртуальный адрес вевдется в рамках одного процесса. Поэтому в рамках двух процесса адреса, отобрадаемые в программе, могут быть абсолютно идентичны, но иметь совершенно разное физическое представление.
