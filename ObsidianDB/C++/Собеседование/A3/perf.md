`perf` - штатный инструмент Linux для анализа производительности
`perf` позволяет посмотреть параметры работы процессора у конкретной программы. Например:
```bash
perf stat ./build/bin/h1_test
```

Всего можно выделить 3 ключевых инструмента `perf`:
* `perf stat` - Сколько ресурсов потребляет программа?
* `perf record` - Где именно тратится `CPU` - время?
* `perf trace` - Какие системные вызовы делает программа?

**Программные события**
- `context-switches` - ядро Linux остановило выполнение потока и переклчала CPU на другой поток. Большое значение `context-switches` симптом частых переключений, значит, программа чего-то постоянно ждёт.
- `cpu-migrations` - миграция потока между логическими `CPU`. Это проблема, ведь `cache` процессора не мигрирует и поэтому, CPU приходтся снова и снова его заполнять
- `page-faults` - ошибки получения страницы виртуальной памяти. Подозрительно, когда ошибок становиться черезмерно много в моменте. Это значит, что программа начала резко запрашивать виртуальную память
**Аппаратные события**
* `cycle` - сколько тактов CPU прошло, пока код исполнялся на данном типе ядер
* `instructions` - число машинных инструкций, которые CPUзавершил
* `branches` - число инстукций с витвлением (`if/else/switch`)
* `branch-misses` - современные CPU пытаются угадать, куда пойдет программа. Они заранее подгружают необходимые переменные для блоков. Если CPU промахнулся `miss`, то работа программы замедляется

Утилизация CPU - показатель насколько эффективно процесс занимал процессор во время своего существования.

**Пример:**
```bash
0,014385453 seconds time elapsed
0,007051000 seconds user
0,003917000 seconds sys
```

* `time elapsed` - Сколько времени работала программа
* `user` - время работы в `user space`
* `sys` - время работы в `kernal space`

```text
CPU time=user + sys

0,007051000 + 0,003917000 = 0.01096800

CPU utilization = CPU time / time elapsed = 0.01096800 / 0,014385453 = 0.762
```
Таким образом, `76%` мощности одного ядра было использована при работе программы.
