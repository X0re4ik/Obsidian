# Общие вопросы по STL

## `std::vector`

### Расскажи, как устроен std::vector под капотом.

`std::vector` хранит элементы в **непрерывном участке памяти**, который выделяется с помощью **аллокатора**. Внутри обычно три указателя: на начало данных, на элемент за последним (`end_`) и на конец выделенной памяти (`end_of_storage_`). Размер объекта на 64-битной системе - 24 байта, но стандарт этого не гарантирует. `size` - число элементов, `capacity` - доступная вместимость. При нехватке места выделяется новый буфер, элементы перемещаются или копируются, а старый освобождается.

### Назови алгоритмическую сложность операций вставки/поиска/удаления для `std::vector`

* `push_back` / `emplace_back` - амортизированно `O(1)`, но `O(N)` при релокации памяти
* `insert` - `O(N)` в начале или середине, в конец - амортизированно `O(1)`
* `std::find` - `O(N)`
* `[]` и `.at()` - `O(1)`
* `clear` - `O(N)`
* `erase` - `O(N)` в начале или середине, последний элемент - `O(1)`

### Есть std::vector из 100 элементов, как работает механика добавления 101 элемента? Добавили 101 элемент, что произойдет при удалении этого элемента?

Есть `std::vector` из 100 элементов.
1. Если `capacity() > 100`, 101-й элемент будет создан в конце: `size()` станет 101, а `capacity()` не изменится.
2. Если `capacity() == 100`, свободного места нет. `vector` выделит новый блок памяти большей ёмкости, переместит или скопирует туда старые элементы, создаст 101-й элемент и освободит старый блок. Точный рост capacity не гарантирован.

При `pop_back()` вызовется деструктор 101-го элемента, `size()` уменьшится до 100, а `capacity()` останется прежней.

### Когда лучше выбирать std::deque, а когда std::vector?

У `std::deque` есть огромное преймущество: добавление в конец и в начало за `O(1)`. Он поддерживает доступность элементов по произвольному доступу за `O(1)`.
Но главное преимущество `std::vector` в его простате, он представляет непрерывный блок памяти, что увеличвает его скорость на больших массивах данных (в т.ч. за счёт попадания кэш-а процессора), возможность управлять размером `capacity` и поддерживать `C API` в виде `.data()`
`std::deque` хорош в довольно узких специализированных задачах по типу реализации скользящего окна и `fifo`


### Что произойдет с итераторами std::vector после вставки/удаления элемента?

Если при вставке не произошла реаллокация, `push_back()` инвалидирует только старый `end()`: итераторы на существующие элементы остаются валидны.
`insert(it, obj)` инвалидирует итератор `it`, все итераторы после него и старый `end()`, потому что элементы с позиции вставки сдвигаются вправо. Корректно сохранить результат так: `it = v.insert(it, obj)`.
`erase(it)` инвалидирует `it`, все итераторы после него и старый `end()`, так как элементы справа сдвигаются влево. Корректная запись: `it = v.erase(it)`.
`pop_back()` инвалидирует итератор на удалённый последний элемент и старый `end()`.
Если любая вставка вызвала реаллокацию, инвалидируются все итераторы, ссылки и указатели на элементы `std::vector`.

### Чем emplace_back отличается от push_back

`emplace_back` конструирует объект непосредственно в памяти вектора, принимая аргументы его конструктора. `push_back` принимает уже созданный объект и копирует или перемещает его. Поэтому при передаче временного объекта `push_back` обычно вызывает перемещение, а `emplace_back` создаёт объект сразу на месте.

```C++
struct User {
  User() { std::cout << "User()\n"; }
  User(const User&) { std::cout << "User(const User&)\n"; }
  User(User&&) noexcept { std::cout << "User(User&&)\n"; }
};

int main() {
  std::vector<User> source;
  source.reserve(10);
  source.push_back(User{});     // User() -> User(User&&)
  source.emplace_back();        // User()
  return 0;
}
```

## std::map

### Расскажи, как устроен std::map под капотом.

`std::map` - это отсоритрованный контейнер, который содержит пары `key/value` значений с уникальностью по ключу. Обычно `std::map` представляет из себя реализацию красно-черного дерева (сбалонсированное двоичное дерево поиска)

**Отметим:**
* У кажого узла дерева может быть не более двух потомков
* Объекты в дереве упорядочены
* Все значения меньше `N` попадают  в левое поддерево, все знаения больше `N` вправое.
* Для каждого узла высоты его правого и левого поддерева примерно равны (в некоторых реализациях они могут отличаться не более чем на 1)

### Назови алгоритмическую сложность операций вставки/поиска/удаления для std::map.

Операции вставки/поиска/удаления дереве будут `O(log(N))`. Теоретически каждая мутабельная операция над деревом может привеси к его перебалансировке, но перебаласировка обычно имеет правила к высоте и "количеству перекрашиваний", так что значимого влияния на скорость операций не даёт. Процесс перебалансировки очень важен, так как не дает дереву "деградировать" в последовательность со скоростью `O(N)`

### Что произойдет с итераторами std::map после перестроения дерева?

Перебалансировка std::map не инвалидирует итераторы, так как элементы хранятся в отдельных узлах дерева и не перемещаются. При erase инвалидируется только итератор на удалённый элемент
### Как использовать свои структуры данных в качестве ключей в std::map?

Так как, `std::map` использует сбалансированное дерево, то для того, чтобы использовать свои структры данных необходимо либо:

1) Опредлить метод `operator<` для структуры
2) Описать свой собственный компаратор

**Пример:**
Вариант 1:
```C++
struct Point {
  int x, y;

  bool operator<(const Point &other) const { return x + y < other.x + other.y; }
};

int main() {
  std::map<Point, int> point_map;
  point_map.insert({Point{1, 2}, 1});
}
```
Вариант 2
```C++
struct Point {
  int x, y;
};

class PointComp {
public:
  bool operator()(const Point &left, const Point &right) const {
    return left.x + left.y < right.x + right.y;
  }
};

int main() {
  std::map<Point, int, PointComp> point_map;
  point_map.insert({Point{1, 2}, 1});
}
```

Требования к сравнению:
1) `a < a` - `false`
2) если `a < b`, то `! (b < 1)`
3) транзитивность
4) если `!(a<b) && !(b<a)`, то `a` эвивалентно `b`

## std::unordered_map

### Расскажи, как устроен std::unordered_map под капотом.

`std::unordered_map` - это ассоциативный контейнер, содержащий пары ключ-значение с уникальными ключами. Поиск, вставка и удаление элементов имеют среднюю постоянную сложность. Внутри элементы не сортируются в каком-либо определённом порядке, а организованы в сегменты. В какой сегмент помещается элемент, полностью зависит от хеша его ключа.

Уппрощенно хранение объектов внтури `std::unorderd_map` можно представить так:
```C++
#include <cstddef>
#include <functional>
#include <list>
#include <utility>
#include <vector>
#include <stdexcept>

template <
    class Key,
    class Value,
    class Hash = std::hash<Key>,
    class KeyEqual = std::equal_to<Key>
>
class UnorderedMap {
public:
    using key_type        = Key;
    using mapped_type     = Value;
    using value_type      = std::pair<const Key, Value>;
    using size_type       = std::size_t;
    using hasher          = Hash;
    using key_equal       = KeyEqual;

private:
    // Bucket — двусвязный список пар. std::list не инвалидирует
    // итераторы при вставке/удалении других элементов.
    using Bucket = std::list<value_type>;

    std::vector<Bucket> buckets_;
    size_type           size_     = 0;
    float               max_load_ = 1.0f;
    Hash                hash_{};
    KeyEqual            equal_{};

    static constexpr size_type kInitialBuckets = 8;

    size_type bucket_index(const Key& key) const {
        return hash_(key) % buckets_.size();
    }

    void rehash_if_needed() {
        if (static_cast<float>(size_) / buckets_.size() <= max_load_) return;
        rehash(buckets_.size() * 2);
    }

public:
    // ---------- Конструкторы ----------
    UnorderedMap() {
        buckets_.resize(kInitialBuckets);
    }

    explicit UnorderedMap(size_type bucket_count) {
        buckets_.resize(bucket_count ? bucket_count : kInitialBuckets);
    }

    // ---------- Размеры ----------
    size_type size()     const noexcept { return size_; }
    bool      empty()    const noexcept { return size_ == 0; }
    size_type bucket_count() const noexcept { return buckets_.size(); }
    float     load_factor()  const noexcept {
        return static_cast<float>(size_) / buckets_.size();
    }
    float     max_load_factor() const noexcept { return max_load_; }
    void      max_load_factor(float f) noexcept { max_load_ = f; }

    // ---------- Вставка / доступ ----------
    std::pair<value_type*, bool> insert(const value_type& kv) {
        rehash_if_needed();
        auto& bucket = buckets_[bucket_index(kv.first)];
        for (auto& p : bucket) {
            if (equal_(p.first, kv.first)) {
                return {&p, false};   // ключ уже есть
            }
        }
        bucket.push_back(kv);
        ++size_;
        return {&bucket.back(), true};
    }

    // operator[] — вставляет значение по умолчанию, если ключа нет
    Value& operator[](const Key& key) {
        rehash_if_needed();
        auto& bucket = buckets_[bucket_index(key)];
        for (auto& p : bucket) {
            if (equal_(p.first, key)) return p.second;
        }
        bucket.emplace_back(key, Value{});
        ++size_;
        return bucket.back().second;
    }

    // at() — бросает, если ключа нет
    Value& at(const Key& key) {
        auto& bucket = buckets_[bucket_index(key)];
        for (auto& p : bucket) {
            if (equal_(p.first, key)) return p.second;
        }
        throw std::out_of_range("UnorderedMap::at: key not found");
    }

    const Value& at(const Key& key) const {
        auto& bucket = buckets_[bucket_index(key)];
        for (const auto& p : bucket) {
            if (equal_(p.first, key)) return p.second;
        }
        throw std::out_of_range("UnorderedMap::at: key not found");
    }

    // ---------- Поиск ----------
    value_type* find(const Key& key) {
        auto& bucket = buckets_[bucket_index(key)];
        for (auto& p : bucket) {
            if (equal_(p.first, key)) return &p;
        }
        return nullptr;
    }

    const value_type* find(const Key& key) const {
        auto& bucket = buckets_[bucket_index(key)];
        for (const auto& p : bucket) {
            if (equal_(p.first, key)) return &p;
        }
        return nullptr;
    }

    bool contains(const Key& key) const { return find(key) != nullptr; }

    // ---------- Удаление ----------
    bool erase(const Key& key) {
        auto& bucket = buckets_[bucket_index(key)];
        for (auto it = bucket.begin(); it != bucket.end(); ++it) {
            if (equal_(it->first, key)) {
                bucket.erase(it);
                --size_;
                return true;
            }
        }
        return false;
    }

    void clear() {
        for (auto& b : buckets_) b.clear();
        size_ = 0;
    }

    // ---------- Рехэширование ----------
    void rehash(size_type new_count) {
        if (new_count < kInitialBuckets) new_count = kInitialBuckets;

        std::vector<Bucket> new_buckets(new_count);

        for (auto& bucket : buckets_) {
            for (auto& p : bucket) {
                size_type idx = hash_(p.first) % new_count;
                new_buckets[idx].push_back(std::move(p));
            }
        }

        buckets_ = std::move(new_buckets);
    }
};
```

### Назови алгоритмическую сложность операций вставки/поиска/удаления для std::unordered_map.

Если ключ имеет "хорошую" хеш-функцию, то операции удаления/вставки/поиска будут `O(1)`, но если "плохую", то каждая операция буде занимать `O(l)`, где `l` - длина цепочки в бакете.

Хорошая хеш-функция - это функция, которая возвращает уникальный индекс объекта, что позволяет иметь короткие цепочки внтури бакета
