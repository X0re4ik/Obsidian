## Что такое идиома RAII? Напиши код. Приведи примеры RAII в STL.

RAII (Resource Acquisition Is Initialization) связывает владение ресурсом со временем жизни объекта. Ресурс захватывается при инициализации и освобождается в деструкторе, в том числе при раскрутке стека из-за исключения.

Примеры стандартной библиотеки: `std::unique_ptr`, `std::vector`, `std::string`, `std::lock_guard`, файловые потоки.

```cpp
#include <memory>
#include <stdexcept>

void work() {
    auto data = std::make_unique<int[]>(100);
    throw std::runtime_error("failure");
} // data освобождает массив при раскрутке стека
```

RAII применима не только к памяти: `std::lock_guard` освобождает мьютекс, а файловый поток закрывает файл. Если конструктор не завершился, деструктор самого объекта не вызывается, но уже созданные RAII-поля уничтожаются. Поэтому владение ресурсом нужно сразу передавать RAII-объекту.

## Что такое RVO? Напиши код.

RVO - (Return Value Optimization) - устранение промежуточного копирования или перемещения при возврате объекта по значению: результат создаётся сразу в месте назначения

RVO неразрывно связано с понятием `prvalue` (`pure value`)

Пример для сравнения: C++14 с `-fno-elide-constructors` и C++17. В C++17 этот флаг не отключает обязательное прямое создание результата из prvalue того же типа.
```C++
#include <iostream>

class A {
public:
  A() { std::cout << "A()" << std::endl; }
  A(const A &) { std::cout << "A(const A&)" << std::endl; }

  ~A() { std::cout << "~A()" << std::endl; }
};

A getA() {
  return A(); // (1)
}

int main() {
  auto a = getA(); // (2)
  return 0;
}

```

Вывод для C++14 с `-fno-elide-constructors`:
```text
A()
A(const A&)
~A()
A(const A&)
~A()
~A()
```
До C++17 без устранения копий сначала создаётся временный объект в `getA`, затем копия результата функции и затем объект `a`. С C++17 в выражении `A a = getA()` при `return A()` результат создаётся напрямую, без промежуточных копий. Это правило для prvalue того же типа; NRVO остаётся необязательной.
```text
A()
~A()
```

Рассмотрим пул сценариев, когда отрабатывает `RVO`:

1) Возврат временного объекта (`prvalue`) 🟢
```C++
A getA() {
  return A();
}
```
2) Возврат локального объекта (`NRVO`) 🟡
`NRVO` не является обязательным даже после `C++17`, но большинство компиляторов ее используют
```C++
A getA() {
  auto x = A();
  return x;
}
```
3) Возврат различных объектов в зависимости от условия
```C++
A getA(int x) {
  if (x > 0) {
    auto x = A();
    return x; // NRVO возможна, но не гарантирована
  } else {
    auto y = A();
    return y; // NRVO возможна, но не гарантирована
  }
}
```
Разные ветви сами по себе не запрещают NRVO. В этом примере времена жизни локальных объектов не пересекаются; компилятор может разместить каждый из них сразу в результате.
4) `RVO` не сработает при возврате параметра объекта 🔴
```C++
A getA(A a) {
  return a;
}
```
5) Возврат значения через `std::move`
```C++
A getA() {
  auto tmp = A();
  return std::move(tmp); // Не использовать Анти-паттерн
}
```
`return std::move(tmp)` мешает NRVO для локального `tmp`. Обычно следует писать `return tmp`: компилятор может устранить копирование, а иначе попробует перемещение. Если подходящего перемещения нет, возможно копирование; `std::move` сам по себе не гарантирует move-конструктор.

## Что такое NRVO? Напиши код.

`NRVO` (`Named Return Value Optimization`) - частный случай `RVO`, связанный с возвратом именнованных локальных объектов из функции.

```C++
A getA() {
  auto x = A();
  return x; // NRVO
}
```

NRVO необязательна даже в C++17 и новее. В примере `A` - класс из предыдущего ответа.

## Что такое SSO?

SSO (Small String Optimization) - оптимищация, которая применяется в шаблоне класса `std::basic_string` и его аналогов.

Данная оптимизация строится вокруг того, что хранение маленьких объектов строк в куче - дорого. Можно избежать отдельного выделения памяти, храня символы внутри самого объекта строки. Сам объект может находиться и на стеке, и в куче.

Для того, чтобы иметь выбор:
- Хранение коротких строк внутри объекта
- Хранение в куче больших строк
Есть специальный тип `union` - поля которого делят один и тот же участок оперативной памяти.
* Размер `union` достаточен для самого большого поля с учётом требований выравнивания. В любой момент времени в нем хранится только одно значение
* Полезно, когда переменная должна содержать разные типы данных в разное время, но не одновременно

**Проблема**
```C++
class string
{
  size_t capacity;
  char *buf;
  size_t size;
};
```
В типичной 64-битной реализации эти три поля занимают 24 байта. Без SSO даже для короткого непустого текста потребуется отдельный буфер. Но перемещение может передать указатель без новой аллокации.
**Решение:**
```C++
class string
{
  size_t capacity;

  union
  {
    struct 
    {
      char *ptr;
      size_t size;
    } heapbuf;

    char stackbuf[sizeof(heapbuf)];
  };
};
```
Теперь класс может быть либо обычным классом с указателем и размером (для больших строк), либо состоящим из `capacity` и `char stackbuf[sizeof(heapbuf)];` (`16 байт`), таким образом строка до 15 символов (1 символ на `\0`)

Это схема хранения, а не готовая реализация строки: ещё нужны размер короткой строки и признак активного режима. SSO и её порог стандартом не гарантируются и зависят от реализации.

## Что такое PIMPL?

Это идеома, которая позволяет скрыть детали реализации в отдельном вспомогательном классе, а в заголовочном файле оставить только указатель на него. 

**Пример:**
`MyClass.h`
```cpp
#pragma once
#include <memory> // Для unique_ptr

// Forward declaration тела
class MyClassImpl;

class MyClass {
public:
    MyClass();
    ~MyClass(); // Должен быть объявлен, т.к. unique_ptr требует полного типа в деструкторе

    // Поддержка перемещения (move)
    MyClass(MyClass&& other) noexcept;
    MyClass& operator=(MyClass&& other) noexcept;

    // Запрещаем копирование (или реализуем через pimpl)
    MyClass(const MyClass&) = delete;
    MyClass& operator=(const MyClass&) = delete;

    // Публичный интерфейс
    void doSomething();
    int getValue() const;

private:
    std::unique_ptr<MyClassImpl> pImpl;
};
```
`MyClass.cpp`
```C++
#include "MyClass.h"
#include <iostream>
#include <string>
#include <vector>

// Полное определение скрытой структуры
class MyClassImpl {
public:
    void doSomething() {
        std::cout << "Doing something with: " << name << std::endl;
    }

    int getValue() const {
        return counter * 2;
    }

    // Реальные данные, которые раньше засоряли бы заголовок
    std::string name;
    int counter = 42;
    std::vector<int> hugeCache;
};

// Реализация методов класса-обертки
MyClass::MyClass() : pImpl(std::make_unique<MyClassImpl>()) {
    pImpl->name = "Hidden";
}

MyClass::~MyClass() = default; // Здесь unique_ptr удаляет Impl

MyClass::MyClass(MyClass&& other) noexcept = default;
MyClass& MyClass::operator=(MyClass&& other) noexcept = default;

void MyClass::doSomething() {
    pImpl->doSomething();
}

int MyClass::getValue() const {
    return pImpl->getValue();
}
```

Преимущества:
1) Увеличение скорости компиляции при изменении только единицы трансялции
2) Сокрытие информации

## Что такое идиома copy-and-swap

**Copy-and-swap** - идиома C++, которая помогает безопасно реализовать оператор присваивания для класса, владеющего ресурсом. Сначала создаётся независимая копия правого операнда, затем состояния объектов обмениваются через `swap`. Если создание копии бросит, исходный объект не изменится. Сильная гарантия требует небросающего обмена и освобождения старого ресурса
**Пример**
```C++
T& operator=(T other) {
    swap(other);
    return *this;
}
```

Тогда при выражении `a = b` происходит следующее:
1) Создается отдельная временная переменная `other` через конструктор копирования (или конструктор перемещения)
2) `other` попадает в `swap`, где происходит обмен данными (минуя исключения), текущий класс получает актуальные данные `other`, а `other` старые данные текущего объекта
3) При выходе из `operator=` временная переменная `other` уничтожается

**Пример**
```C++
#include <algorithm>
#include <cstddef>
#include <utility>

class Buffer {
public:
    explicit Buffer(std::size_t size)
        : data_(size ? new int[size]{} : nullptr),
          size_(size) {}

    Buffer(const Buffer& other)
        : data_(other.size_ ? new int[other.size_] : nullptr),
          size_(other.size_)
    {
        if (size_ != 0) {
            std::copy_n(other.data_, size_, data_);
        }
    }

    Buffer(Buffer&& other) noexcept
        : data_(std::exchange(other.data_, nullptr)),
          size_(std::exchange(other.size_, 0)) {}

    ~Buffer() {
        delete[] data_;
    }

    void swap(Buffer& other) noexcept {
        using std::swap;
        swap(data_, other.data_);
        swap(size_, other.size_);
    }

    Buffer& operator=(Buffer other) {
        swap(other);
        return *this;
    }

private:
    int* data_ = nullptr;
    std::size_t size_ = 0;
};


Buffer a(100);
Buffer b(200);

a = b;             // параметр other создаётся copy constructor
a = std::move(b);  // параметр other создаётся move constructor
```
