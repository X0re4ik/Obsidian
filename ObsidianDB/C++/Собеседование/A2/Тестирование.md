
## Что такое тестирование? Зачем оно нужно?

Тестирование - это процесс проверки работоспособности системы. Необходимо оно для того, чтобы убедиться, что система полностью соответсвует всем предъявляемым ей требованиям

## В чем отличие юнит-тестов от интеграционных тестов?

**Unit-тестирование** - это тестирования работы системе в отрыве от внешних частей, то есть тестирования алгоритмов/бизнес-сценариев/валидации/расчёты в отрыве от интеграции с конкретными доменами.

**Интеграционное тестирование** предполагает тестирования совместное с внешнеми системами. В интеграционном тесте важно убедиться, что данные действительно дошли до внешней системы и могут быть там корректно прочитаны. Например, подключенной БД или `kafka`, где проверка происходит и того, что на самам деле попало во внешнюю систему.

## Что такое mock-тест?

mock-тесты, это из мира unit-тестирования. Например: у нас нет возможности физически сходить в БД и положить туда какое-то значение. Тогда мы используем mock-ки - специальные классы, которые эмулируют заимодействие с внешней системой.
mock-тестирование требует от разработчика в том числе и правильной архитектуры сервиса, так как легке и проще "замокать" класс, который содержит 1 метод и выполняет одну конкретную операцию с внешней системой.

**Пример mock тестирования на `GoogleTest`**
```C++
#include <gmock/gmock.h>
#include <gtest/gtest.h>

#include <string>

class IEmailSender {
public:
    virtual ~IEmailSender() = default;

    virtual bool send(
        const std::string& recipient,
        const std::string& message
    ) = 0;
};

class RegistrationService {
public:
    explicit RegistrationService(IEmailSender& email_sender)
        : email_sender_(email_sender) {}

    bool register_user(const std::string& email) {
        return email_sender_.send(
            email,
            "Hello"
        );
    }

private:
    IEmailSender& email_sender_;
};

class MockEmailSender : public IEmailSender {
public:
    MOCK_METHOD(
        bool,
        send,
        (const std::string& recipient, const std::string& message),
        (override)
    );
};

TEST(RegistrationServiceTest, SendsWelcomeEmailToRegisteredUser) {
    MockEmailSender email_sender;
    RegistrationService service{email_sender};

    EXPECT_CALL(
        email_sender,
        send(
            "xoore4ik@gmail.con",
            "Hello"
        )
    )
        .Times(1)
        .WillOnce(testing::Return(true));

    const bool result = service.register_user("xoore4ik@gmail.con");

    EXPECT_TRUE(result);
}
```

## Как ты контролируешь уровень покрытия кода тестами?

Я пишу на двух языках: `python` и `C++`
На python  есть библиотека `covarage`, которая интегрируется с `pytest` и способна обрабатывать различные сценарии.
На `C++` есть библиотека `llvm-cov` от компилятора `Clang`, которая генерирует подробный отчет по результатам тестирования

Тестирование при помощи `llvm-cov` состоит из нескольких шагов:
1) Создание бинарного файла с тестами и опциями: 
* `-fprofile-instr-generate` - фла
* `-fcoverage-mapping` - 
2) Запустить тесты указаф название профайл файла:
```bash
LLVM_PROFILE_FILE="<test>.profraw" ./<path_to_test>
```
`.profraw` это файл, который содержит информация о том, какие функции и ветки `if/else` были вызваны при работе программы
3) Индексация профиля
Файл `.profraw` является сырым представлением вызова всех функций и их счётчиков. Далее необходимо конвертировать эти данные в понтный `llvm-cov` файл `.profdata`.
```bash
llvm-profdata merge \
	-sparse \
	<path_to_.profraw> \
	-o <path_to_.profdata>
```
4) Генерация html
```bash
llvm-cov show \
	./<path_to_test> \ # Путь до исполняемого файла тестов
	-instr-profile=<path_to_.profdata> \ # Путь до файла .profdata
	-format=html \
	-output-dir=coverage_html \
	-show-line-counts-or-regions \
	-show-branches=percent \
	src/ # Учитывать только тесты из файла src/
```
