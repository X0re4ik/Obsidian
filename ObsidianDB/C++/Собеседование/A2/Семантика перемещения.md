## Что такое семантика перемещения?

Семантика перемещения - совокупность правил языка C++, предназанченных для перемещения объектов время жизни объектов, которых скоро истечёт вместо их копирования.

В `C++` семантика перемещения реализуется через оператор move-присвоения `T& operator=(T&&)` и move-конструктор `T(T&&)`

**Пример**
```C++
struct A {
private:
  std::string str_;

public:
  A(std::string &&str) : str_(std::move(str)) {
    std::cout << "A(std::string&& str)" << std::endl;
  }

  A(const std::string &str) : str_(str) {
    std::cout << "A(const std::string &str)" << std::endl;
  }
};

A foo() {
  std::string str = "I Love C++";
  auto ret = A(str);
  std::cout << "foo: " << str.size() << std::endl;
  return ret;
}

A boo() {
  std::string str = "I Love C++";
  auto ret = A(std::move(str));
  // Потеряли владение над данными `str`, теперь данными владет `ret`
  // `str` живой и валидный, но данные забрал `ret`
  std::cout << "boo: " << str.size() << std::endl;
  return ret;
}

int main() {
  foo();
  // A(const std::string &str)
  // foo: 10
  boo();
  // A(std::string&& str)
  // boo: 0
  return 0;
}
```

## Что такое deep copy и shallow copy?

`deep copy` - глубокое копирование объекта
`shallow copy` - поверхностное копирование объекта

При глубоком копирование объекта происходит глбокое копирование всех его полей, что может быть затратно по ресурам

**Поверхностное копирование** - это копирование объекта, как есть (`memberwise copy`), то есть копирование только полей класса. При поверхностном копировании в случаи указателей мы можем изменять данные одного объекта через другого.

**Глубокоое копирование** - это копирование, при котором каждое поле класса так же подвержено глубокоому копированию. При глубоком копировании происходит полное дублирование данных, таким образом мы не можем влиять на один объект через другого.

**`deep copy` vs `shallow copy`**

**Пример shallow copy**
```C++
struct A {
  int *x;
};

int main() {
  auto a1 = A{new int(10)};
  auto a2 = a1;
  *a1.x = 20;
  std::cout << *a2.x << std::endl;
  // 20
  std::cout << a1.x << " = " << a2.x << std::endl;
  // 0x647d9f21ceb0 = 0x647d9f21ceb0
  return 0;
}
```

**Пример `deep copy`**
```C++
struct A {
  int *x;
  A(int x) : x(new int(x)) {}
  A(const A &a) { x = new int(*a.x); }
  A &operator=(const A &a) {
	// Выделяем ресурс
    int* tmp = new int(*a.x);
    // Освобождаем ресурс
    delete x;
    // Присваиваем ресурс
    x = tmp;
    return *this;
  }
  ~A() { delete x; }
};

int main() {
  auto a1 = A{10};
  auto a2 = a1;
  *a1.x = 20;
  std::cout << *a2.x << std::endl;
  // 10
  std::cout << a1.x << " = " << a2.x << std::endl;
  // 0x5c94a490eeb0 = 0x5c94a490eed0
  return 0;
}
```


## Что такое rvalue и lvalue? Какие ещё категории значений ты знаешь?

**lvalue** (`locator value`) представляет собой объект, который занимает идентифицируемое место в памяти (например, имеет адрес)
* Есть адрес в памяти
* Живёт дольше одного выражения
* `int x` - `lvalue`

**rvalue** — это выражение, которое _не представляет_ собой объект, который занимает идентифицируемое место в памяти

**pvalue** (чистый rvalue) — временное значение у которого нет адреса (нельзя применить `&`)
* Нет адреса
* Живёт только до конфа выражения
* `42` - `pvalue`

**xvalue** — выражение, которое имеет адрес, но его ресур можно безопасно украсть
* Вызов функции `std::move`
* Вызов функции возвращающей `T&&`

Особенности:
`*` принимает `rvalue`, но возвращает `lvalue`
`&` принимает `lvalue`, но возвращает `rvalue`



_If P is of the form T&&, where T is a template parameter, and the argument is an lvalue, the type A& is used in place of A for type deduction._

**любое именованное выражение — это lvalue**, даже если его тип — rvalue-ссылка.

**Идеальная передача или perfect forwarding**

Рассмотрим следующий пример:
```C++
void consume(const std::string &) {
  std::cout << "consume(const std::string &)" << std::endl;
}
void consume(std::string &&) {
  std::cout << "consume(std::string&&)" << std::endl;
}

template <typename T> void log_and_consume(T &&value) { consume(value); }

int main() {
  std::string s = "order-42";

  log_and_consume(s);
  log_and_consume(std::string{"order-43"});
  return 0;
}
```
В обоих случаях ((1) и (2)) будет вызвана перегрузка `consume(const std::string &)`, почему так?
Универсальная ссылка внтри именнованных параметров функции является `lvalue` ссылкой, так как имеют:
* Наименование
* Адрес в памяти
Таким образом необходим механизм, который знает изначальное состояние объекта: ravleu или lvalue - таким механизмом являеься std::forward


До поддержки семантики перемещения (C++11) язык обладал двумя категориями выражения - `lvalue` и `rvalue`
Семантика перемещения дала нам новые категории значений: `gvalue`, `pvalue` и `xvalue`

Выражение принадлежит к категории `pvalue`, если оно соответсвует временному неименованному объекту
```C++
int x = i++;
	↑   ↑
	|   pvalue
    lvalue
```
Выражение принадлежит к категории `xvalue`, если это именнованный объект, ресурсы которого могут быть переиспользованы
```C++
static_cast<T&&>(obj)
std::move(obj);
```
Все остальные случаи принадлежат к категории `lvalue`

`С++11` подарил `rvalue` ссылки (именуемые так же универсальными ссылками `&&`)
**Пример 1.1**
```C++
int y = 9;
int&& x = y;
// error: cannot bind rvalue reference of type ‘int&&’ to lvalue of type ‘int’
```
Ошибка из примера 1.1 демонстрирует, что переменная `x` является как раз `pvalue` - частный случай `rvalue`

### `lvalue` ссылки на примерах 

lvalue ссылки могут быть инициализированы только изменяемыми lvalue, поэтому невозможно выполнить запись по типу
```C++
const int& x = 10;
int& y = x;
// error: binding reference of type ‘int&’ to ‘const int’ discards qualifiers

int& z = 6;
// error: cannot bind non-const lvalue reference of type ‘int&’ to an rvalue of type ‘int’
```

Однако мы можем связать `rvalue` с константой `lvalue` ссылкой 
```C++
const int& x = 10; // Valid
```

### `rvalue` ссылки на примерах

`rvalue` ссылки - это ссылка, которая связана с `rvalue` значением через универсальную ссылку (`&&`)
```C++
int&& x = 8; // Valid
```
`rvalue` ссылка не может быть связана с `lvalue`  ссылкой
```C++
int x = 8;
int&& y = x; // error: cannot bind rvalue reference of type ‘int&&’ to lvalue of type ‘int’
```
Наибольшую пользу `rvalue` ссылки приносят в качестве аргумента функции
```C++
void fun(const int &lref) { std::cout << "lvalue reference to const\n"; }
void fun(int &&rref) { std::cout << "rvalue reference\n"; }

int main() {
  int x = 5;
  fun(x); // (1) lvalue reference to const
  fun(5); // (2) rvalue reference
  return 0;
}
```

Остановимся чуть поподробнее на данном примере, почему перегрузки отработали именно в таком порядке, а не наоборот?
В случаи с `rvalue` (`(2)`) подходят обе перегрузки, так как `rvalue` довольно легко кастится к `lvalue`, а вот `lvalue` (`(1)`) подходит исключительная одна перегрузка, так как `lvalue` прикастовать к `rvalue` без переходов в `xvalue` (`std::move` и `std::forward`) невозможно

Зачем понадобилась ссылка на `rvalue`?

Вспомним оператор копирования и присвоения копированием, мы специально помечаем его `const`, потому что хотим, чтобы исходных объект не был изменён.

Но существует сценарий, когда мы исходный объект нам больше не нужен, а данные, что он содержал были бы нам очень полезны.

```C++
class IntArray {
  int *m_arr;
  int m_len;

public:
  IntArray(int len) : m_len(len), m_arr(new int[len]) { log("Constructor"); }
  ~IntArray() {
    log("Destructor");
    delete[] m_arr;
  }
  // Copy Constructor
  IntArray(const IntArray &rhs) {
    log("Copy Constructor");
    m_arr = new int[rhs.m_len];
    m_len = rhs.m_len;
    for (int i = 0; i < m_len; i++)
      m_arr[i] = rhs.m_arr[i];
  }

  void log(std::string msg) {
    std::cout << "[" << this << "] " << msg << std::endl;
  }
};
IntArray func() {
 
  IntArray obj(5);
  return obj;
}

int main() {
  auto x = func();

  return 0;
}
```

```bash
>> g++ main.cpp -o main -fno-elide-constructors
>> ./main

[0x7ffe9e9a4ad0] Constructor
[0x7ffe9e9a4b10] Copy Constructor
[0x7ffe9e9a4ad0] Destructor
Final 0x7ffe9e9a4b10
[0x7ffe9e9a4b10] Destructor
```
Из примера выше видно, что мы создали два объекта `IntArray`, первый из которых нам не особо и нужен был, вот бы был механизм, который бы не создавал новый объект, а использовал ресурсы уже существующего (внутри функции `func`)
Добавим нашему классу специальный move-конструктор
```C++
IntArray(IntArray &&__other) : m_arr(__other.m_arr), m_len(__other.m_len) {
	log("Move Constructor");
	__other.m_arr = nullptr;
	__other.m_len = 0;
}
```

```bash
>> g++ main.cpp -o main -fno-elide-constructors
>> ./main

[0x7ffc09416930] Constructor
[0x7ffc09416970] Move Constructor
[0x7ffc09416930] Destructor
Final 0x7ffc09416970
[0x7ffc09416970] Destructor
```

Мы видим, что отработал move-конструктор и повторного выделения памяти не произошло, а объект `x` (`auto x = func();`) лишь забрал ресурсы у объекта `obj` (`IntArray obj(5)`)
