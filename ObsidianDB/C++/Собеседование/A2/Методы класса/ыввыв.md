
# Что такое список инициализации (member initializer list) и зачем он нужен?

Чтобы понять роль списка инициализации, необходимо рассмотреть процесс конструирования объекта в C++.

## Проблема инициализации в теле конструктора
Рассмотрим простой класс `Point`:

```cpp
class Point {
public:
  int x_;
  int y_;
  
  Point(int x, int y) {
    std::cout << "x=" << x_ << "; y=" << y_ << std::endl; // (1)
    x_ = x;
    y_ = y;
  }
};
```
Создание полей объекта в C++ происходит строго сверху вниз (в порядке их объявления в классе). В момент входа в тело конструктора (строка 1) поля `x_` и `y_` **уже созданы** (для встроенных типов в них будет лежать мусор). Следовательно, в теле конструктора происходит не *инициализация*, а *переприсваивание*.

## Решение: список инициализации
Список инициализации позволяет проинициализировать поля **до входа в тело конструктора**, непосредственно в момент их создания.

```cpp
class Point {
public:
  int x_; 
  int y_; 
  
  Point(int x, int y) : x_{x}, y_{y} { // Инициализация происходит здесь
    std::cout << "x=" << x_ << "; y=" << y_ << std::endl;
  }
};
```

## Порядок инициализации полей
Важно помнить, что список инициализации **не меняет** порядок создания полей. Поля всегда создаются строго в том порядке, в котором они объявлены в самом классе.

```cpp
struct X { X() { std::cout << "X\n"; } };
struct Y { Y() { std::cout << "Y\n"; } };

class Point {
public:
  X x_;
  Y y_;
  
  // Порядок в списке нарушен относительно объявления в классе
  Point(X x, Y y) : y_{y}, x_{x} {} 
};
```
При компиляции такого кода компилятор выдаст предупреждение `-Wreorder`, а вывод программы всё равно будет:
`X`
`Y`

## Почему `const` и ссылки обязательно инициализировать в списке?
Так как внутри тела конструктора выполняется операция *присваивания*, а не инициализации, это накладывает строгие ограничения:

1. **Константы (`const`):** Константы не могут быть изменены после создания. Если не инициализировать их в списке, они создадутся с дефолтным (или мусорным) значением, и переприсвоить их в теле конструктора будет уже нельзя.
2. **Ссылки (`&`):** Ссылка в C++ обязана ссылаться на существующий объект в момент своего рождения. Оставить её неинициализированной "на потом" технически невозможно.

*Пример ошибки компиляции:*
```cpp
class Point {
public:
  X& x_;
  const Y y_;
  
  Point(X& x, Y y) {
    x_ = x; // Ошибка: ссылка должна быть проинициализирована при создании
    y_ = y; // Ошибка: константный объект нельзя переприсвоить
  }
};
```

## Влияние на производительность (Performance)
Для пользовательских типов (например, сложных классов) отказ от списка инициализации приводит к выполнению двойной работы:
1. До входа в тело конструктора создается объект и вызывается его **конструктор по умолчанию**.
2. Внутри тела конструктора вызывается **оператор присваивания** (`operator=`).

Использование списка инициализации позволяет сразу вызвать нужный конструктор (копирования или перемещения), избегая лишних операций инициализации по умолчанию и последующего переприсваивания.
