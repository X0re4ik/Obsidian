## Общие знания по ООП

### 1. Что такое ООП?

**ООП (Объектно-ориентированное программирование)** - это методология программирования, в которой программа строится из объектов, объединяющих данные и методы их обработки. Основные принципы: инкапсуляция, наследование и полиморфизм.

[[Общие знания по ООП#Что такое ООП?|Полный ответ]]

### 2. Что такое класс?

**Класс** - это шаблон (чертёж) для создания объектов, описывающий их свойства (поля) и поведение (методы)

[[Общие знания по ООП#Что такое класс?|Полный ответ]]

### 3. Что такое объект?

**Объект** - это экземпляр класса, конкретная сущность, созданная по шаблону, со своими 
значениями свойств и доступными методами

[[Общие знания по ООП#Что такое объект?|Полный ответ]]

### 4. Расскажи про основные принципы ООП: абстракция, наследование, полиморфизм, инкапсуляция.

**Абстракция** - выделение существенных свойств объекта и скрытие ненужных деталей.

**Инкапсуляция** - размещение данных и методов в одном компоненте с контролем доступа к внутреннему состоянию.

**Наследование** - создание класса на основе уже существующего, заимствуя его поля и методы.

**Полиморфизм** - возможность работать с разными типами через общий интерфейс, получая поведение соответствующего типа.

[[Общие знания по ООП#Расскажи про основные принципы ООП: абстракция, наследование, полиморфизм, инкапсуляция.|Полный ответ]]

### 5. Что такое АБК (Абстрактный Базовый Класс)? Что такое интерфейс?

АБК - базовый класс, в котором хотя бы одна виртуальная функция остаётся чистой (`= 0`), в том числе унаследованная без переопределения. Его нельзя инстанцировать. Он может содержать поля и реализацию методов.

Интерфейс - контракт, определяющий операции, которые должен поддерживать класс. В C++ его обычно выражают абстрактным классом с публичными чистыми виртуальными методами и виртуальным деструктором.

### 6. Расскажи про принципы SOLID.

SOLID:

* S - Класс должен закрывать только одну потребность.
* O - Класс должен быть открыт для расширения, но закрыт для модификации.
* L - Производный класс должен заменять базовый без нарушения его контракта.
* I - Много специализированных интерфейсов лучше, чем один универсальный.
* D - Высокоуровневые и низкоуровневые модули должны зависеть от абстракций. Детали реализации зависят от абстракций, а не наоборот.

[[Общие знания по ООП#Расскажи про принципы SOLID.|Полный ответ]]

### 7. Что такое модификаторы доступа? Расскажи про public, private, protected.

**public:** - полная открытость данных, клиент может свободно обращаться к методам и полям в блоке public

**private** - полная закрытость данных, ни клиент, ни дочерний класс не может получить поля или вызвать методы в блоке private

**protected** - открытость полей и методов только для очерних классов, то есть наследник может вызвать методы родителя, но внешнму клиенту вызов protected блока запрещен

В `C++` все поля `struct`-ы по умолчанию `public`, а все поля класса `private`

## Наследование

### 1. Что такое наследование? Какие виды наследования (`public`, `protected`, `private`) ты знаешь? В чём разница между ними?

**Наследование** - механизм, позволяющий объявить класс на основе уже существующего, заимствуя его поля и методы.

`C++` поддерживает 3 режима наследования:
* `public`: public и protected члены базы сохраняют свой уровень доступа.
* `protected`: public и protected члены базы становятся protected.
* `private`: public и protected члены базы становятся private.

Private члены базы напрямую недоступны наследнику при любом режиме.

[[Наследование#Что такое наследование? Какие виды наследования (public, protected, private) ты знаешь? В чём разница между ними?|Полный ответ]]

### 2. Что такое множественное наследование?

`С++` поддерживает множественное наследование. Это когда один класс имеет двух и более родителей.

**Пример**
```C++
struct A { void foo(); };
struct B { void bar(); };

struct C : public A, public B {};
```

[[Наследование#Что такое множественное наследование?|Полный ответ]]

### 3. Что такое ромбовидное наследование (diamond problem)? Как его избежать?

Ромбовидное наследование: `B` и `C` наследуются от `A`, а `D` - от `B` и `C`. В объекте `D` появляются две копии `A`, поэтому обращение к членам `A` становится неоднозначным.

Решение - виртуальное наследование: `B` и `C` наследуются от `A` через `virtual public A`. Тогда в `D` будет одна общая копия `A`.

[[Наследование#Что такое ромбовидное наследование (diamond problem)? Как его избежать?|Полный ответ]]

### 4. Что такое виртуальное наследование?

Виртуальное наследование необходимо для решения задачи ромбовидного наследования. При виртуальном наследовании мы говорим компилятору, что наследуемый класс должен быть в одном экземпляре. За создание отвечает самый производный в цепочке наследования.

```C++
struct A {int x;};
struct B : virtual public A {};
struct C : virtual public A {};
struct D : public B, public C { D() : A{1} {} };
```
