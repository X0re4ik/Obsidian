## Общие знания по ООП

### 1. Что такое ООП?

**ООП (Объектно-ориентированное программирование)** - это методология программирования, в которой программа строится из объектов, объединяющих данные и методы их обработки. Основные принципы: инкапсуляция, наследование и полиморфизм.

### 2. Что такое класс?

**Класс** - это шаблон (чертёж) для создания объектов, описывающий их свойства (поля) и поведение (методы)

[[Общие знания по ООП#Что такое класс?|Полный ответ]]

### 3. Что такое объект?

**Объект** - это экземпляр класса, конкретная сущность, созданная по шаблону, со своими 
значениями свойств и доступными методами

[[Общие знания по ООП#Что такое объект?|Полный ответ]]

### 4. Расскажи про основные принципы ООП: абстракция, наследование, полиморфизм, инкапсуляция.

**Абстракция** - выделение существенных свойств объекта и скрытие ненужных деталей.

**Инкапсуляция** - размещение данных и методов в одном компоненте с контролем доступа к внутреннему состоянию.

**Наследование** - создание класса на основе уже существующего, заимствуя его поля и методы.

**Полиморфизм** - возможность работать с разными типами через общий интерфейс, получая поведение соответствующего типа.

[[Общие знания по ООП#Расскажи про основные принципы ООП: абстракция, наследование, полиморфизм, инкапсуляция.|Полный ответ]]

### 5. Что такое АБК (Абстрактный Базовый Класс)? Что такое интерфейс?

АБК - базовый класс, в котором хотя бы одна виртуальная функция остаётся чистой (`= 0`), в том числе унаследованная без переопределения. Его нельзя инстанцировать. Он может содержать поля и реализацию методов.

Интерфейс - контракт, определяющий операции, которые должен поддерживать класс. В C++ его обычно выражают абстрактным классом с публичными чистыми виртуальными методами и виртуальным деструктором.

[[Общие знания по ООП#Что такое АБК (Абстрактный Базовый Класс)? Что такое интерфейс?|Полный ответ]]

### 6. Расскажи про принципы SOLID.

SOLID:

* S - Класс должен закрывать только одну потребность.
* O - Класс должен быть открыт для расширения, но закрыт для модификации.
* L - Производный класс должен заменять базовый без нарушения его контракта.
* I - Много специализированных интерфейсов лучше, чем один универсальный.
* D - Высокоуровневые и низкоуровневые модули должны зависеть от абстракций. Детали реализации зависят от абстракций, а не наоборот.

[[Общие знания по ООП#Расскажи про принципы SOLID.|Полный ответ]]

### 7. Что такое модификаторы доступа? Расскажи про public, private, protected.

**public:** - полная открытость данных, клиент может свободно обращаться к методам и полям в блоке public

**private** - полная закрытость данных, ни клиент, ни дочерний класс не может получить поля или вызвать методы в блоке private

**protected** - открытость полей и методов только для очерних классов, то есть наследник может вызвать методы родителя, но внешнму клиенту вызов protected блока запрещен

В `C++` все поля `struct`-ы по умолчанию `public`, а все поля класса `private`

## Наследование

### 1. Что такое наследование? Какие виды наследования (`public`, `protected`, `private`) ты знаешь? В чём разница между ними?

**Наследование** - механизм, позволяющий объявить класс на основе уже существующего, заимствуя его поля и методы.

`C++` поддерживает 3 режима наследования:
* `public`: public и protected члены базы сохраняют свой уровень доступа.
* `protected`: public и protected члены базы становятся protected.
* `private`: public и protected члены базы становятся private.

Private члены базы напрямую недоступны наследнику при любом режиме.

[[Наследование#Что такое наследование? Какие виды наследования (public, protected, private) ты знаешь? В чём разница между ними?|Полный ответ]]

### 2. Что такое множественное наследование?

`С++` поддерживает множественное наследование. Это когда один класс имеет двух и более родителей.

**Пример**
```C++
struct A { void foo(); };
struct B { void bar(); };

struct C : public A, public B {};
```

[[Наследование#Что такое множественное наследование?|Полный ответ]]

### 3. Что такое ромбовидное наследование (diamond problem)? Как его избежать?

Ромбовидное наследование: `B` и `C` наследуются от `A`, а `D` - от `B` и `C`. В объекте `D` появляются две копии `A`, поэтому обращение к членам `A` становится неоднозначным.

Решение - виртуальное наследование: `B` и `C` наследуются от `A` через `virtual public A`. Тогда в `D` будет одна общая копия `A`.

[[Наследование#Что такое ромбовидное наследование (diamond problem)? Как его избежать?|Полный ответ]]

### 4. Что такое виртуальное наследование?

Виртуальное наследование необходимо для решения задачи ромбовидного наследования. При виртуальном наследовании мы говорим компилятору, что наследуемый класс должен быть в одном экземпляре. За создание отвечает самый производный в цепочке наследования.

```C++
struct A {int x;};
struct B : virtual public A {};
struct C : virtual public A {};
struct D : public B, public C { D() : A{1} {} };
```

## Методы класса

### 1. Что такое конструктор?

Особый вид метода класса, который автоматически вызывается при создании объекта класса
Особенности конструктора:
* Название идентично названию класса
* Не имеет возвращаемого значения

### 2. Зачем используется ключевое слово `explicit`?

`explicit` нужен для борьбы с неявным преобразованием типа. Конструктор с `explicit` нельзя использовать для неявного преобразования и копирующей инициализации; прямая инициализация разрешена. С C++11 применяется и к операторам преобразования. `explicit operator bool()` допускается в логических контекстах, например `if (obj)`.

### 3. Существует ли виртуальный конструктор?

Нет! Виртуальных конструкторов быть не может.

### 4. Какие виды конструкторов ты знаешь?

1. Конструктор по умолчанию - вызывается без аргументов.
2. Конструктор с параметрами - создаёт объект из переданных значений.
3. Конструктор копирования - создаёт новый объект из другого объекта того же типа.
4. Конструктор перемещения - передаёт ресурсы от другого объекта.
5. Делегирующий конструктор - вызывает другой конструктор того же класса.

[[Методы класса#Какие виды конструкторов ты знаешь?|Полный ответ]]

### 5. Что такое конструктор копирования? Когда компилятор генерирует его неявно?

Конструктор копирования создаёт новый объект из другого объекта того же типа, обычно `T(const T&)`. Неявно объявляется, если пользователь его не объявил. Копирует базы и поля согласно их типам. Будет удалён, если объявлены move-конструктор или move-присваивание; также при невозможности копирования/разрушения баз или полей либо наличии поля rvalue-ссылки. Определение генерируется при необходимости.

[[Методы класса/Что такое конструктор копирования? Когда компилятор генерирует его неявно?|Полный ответ]]

### 6. Что такое оператор присваивания копированием? Чем он отличается от конструктора копирования?

Оператор присваивания копированием переносит состояние другого объекта в уже существующий объект. Конструктор копирования создаёт новый объект. Обычная сигнатура оператора: `T& operator=(const T&)`.

```cpp
T b = a; // Конструктор копирования
b = a;   // Оператор присваивания
```

### 7. Что такое список инициализации (member initializer list)? Почему некоторые поля обязательно нужно инициализировать через него (например, ссылки, const-поля)?

Список инициализации позволяет проинициализировать базы и поля до входа в тело конструктора. Порядок полей определяется их объявлением, а не порядком в списке. Ссылку нужно сразу связать с объектом, а const-полю нельзя присвоить значение в теле конструктора. Альтернатива для полей - инициализатор при объявлении. Список также позволяет вызвать конструктор базы или поля с аргументами.

### 8. Что такое виртуальная функция?

Виртуальная функция - функция-член, которую можно переопределить в производном классе. Вызов через указатель или ссылку разрешается в соответствии с динамическим (фактическим) типом объекта. В базе объявляется через `virtual`; переопределение остаётся виртуальным без повторного `virtual`. Вызов реализации базы можно указать явно: `obj.Base::f()`.

[[Методы класса#8. Что такое виртуальная функция?|Полный ответ]]

### 9. Что такое `vtable`? Расскажи, как она работает.

`vtable` - таблица адресов виртуальных функций и служебных данных, создаваемая компилятором для полиморфного класса. Объект обычно хранит указатель `vptr`: при виртуальном вызове через него выбирается нужная функция из таблицы. Таблицы общие для объектов типа; при множественном наследовании их может быть несколько. Это типичная реализация, а не требование стандарта.

### 10. Зачем используется ключевое слово `virtual`?

Ключевое слово `virtual` объявляет виртуальный метод: при вызове через указатель или ссылку на базовый класс выбирается реализация по фактическому типу объекта. Также применяется для виртуального наследования.

### 11. Зачем используется ключевое слово `final`?

Ключевое слово `final` указывает, что виртуальная функция не может быть переопределена в производном классе или что класс не может наследоваться.

### 12. Зачем используется ключевое слово `override`?

Начиная с C++11 появилось ключевое слово `override`, которое позволяет явно сказать компилятору, что эта функция переопределяет виртуальную функцию родителя. Это позволяет нам избавиться от ошибок, когда вместо переопределения мы случайно создали новый метод с чуть иными параметрами.

Если подходящего виртуального метода базы нет, компилятор выдаст ошибку.

### 13. Что такое чистая виртуальная функция?

Чистая виртуальная функция - виртуальный метод, объявленный с `= 0`. Пока в классе остаётся такая функция без переопределения, класс абстрактный. У чистой виртуальной функции может быть реализация вне класса; это не отменяет её чистоту.

**Пример:**
```C++
class Base1 {
public:
  // Чисто виртуальная функция
  virtual void base_1() = 0;
};
```

### 14. Как получить ошибку `pure virtual call`? Напиши код.

Виртуальный вызов чистой виртуальной функции из конструктора или деструктора того же объекта - UB. Типичная диагностика: `pure virtual call`, но она не гарантирована.

```cpp
struct Base {
    Base() { call(); }
    void call() { f(); }
    virtual void f() = 0;
};
struct Derived : Base {
    void f() override {}
};
int main() { Derived d; }
```

### 15. Что такое деструктор?

Деструктор — это специальный метод класса, который вызывается автоматически при уничтожении объекта. Его главная цель — деинициализация объекта, то есть освобождение ресурсов (динамической памяти, сетевых сокетов, файловых дескрипторов, мьютексов и т.д.), которые были захвачены за время жизни объекта. 

[[Методы класса#Что такое деструктор?|Полный ответ]]

### 16. Зачем нужен виртуальный деструктор?

Виртуальный деструктор необходим для того, чтобы при удалении объекта производного класса через указатель на базовый класс гарантированно вызывался деструктор наследника (а за ним и базового класса). 

Удаление объекта производного класса через указатель на базовый без виртуального деструктора ведет к **неопределенному поведению (Undefined Behavior, UB)**. На практике это чаще всего выражается в том, что деструктор наследника просто не вызывается, что приводит к утечке ресурсов.

### 17. В чем особенность константных методов класса?

Методы, помеченные спецификатором `const`, не позволяют изменять обычные поля через `this` и вызывать через него неконстантные методы. Их можно вызывать для константных объектов. Сохранение логического состояния - обязанность автора: `mutable` и данные по указателям всё ещё могут изменяться.

### 18. Расскажи Правило 5 (Правило 3, Правило 0). Напиши код.

### 19. Расскажи об использовании `static` для полей и методов класса.

Статическое поле существует в единственном экземпляре для всех объектов класса (у специализаций шаблона свои поля). Обращение: `A::field` или через объект. Статический метод не имеет `this`, не может быть `virtual` или `const`; нестатические поля доступны ему только через конкретный объект. Обычное static-поле определяют вне класса; с C++17 можно использовать `inline static` внутри класса.

### 20. Расскажи об использовании `inline` для полей и методов класса.

`inline` позволяет размещать определения в заголовке, включаемом в несколько единиц трансляции, при соблюдении ODR. Не гарантирует подстановку тела вместо вызова. Метод, определённый внутри класса, неявно inline (вне именованного модуля). С C++17 `inline static` поле можно определить и инициализировать в классе: это одно общее поле. К нестатическим полям `inline` неприменим.

### 21. Зачем используется ключевое слово `mutable` (для полей класса, для лямбды)?

Для поля класса `mutable` разрешает изменение даже у константного объекта или внутри `const` метода. Для лямбды делает `operator()` неконстантным, позволяя менять захваченные по значению копии. Исходная переменная при этом не меняется.

### 22. Что такое object slicing (срезка типа)? Приведи пример, когда это происходит.

**Object slicing** - это ситуация, когда объект производного класса копируют в объект базового класса по значению, поэтому сохраняется только базовая часть объекта, а данные и поведение, специфичные для потомка, теряются.

```cpp
struct Animal {};
struct Dog : Animal { int age = 3; };
Dog dog;
Animal animal = dog; // Срезка: age не копируется
```

## Семантика перемещения

### 1. Что такое семантика перемещения?

Семантика перемещения позволяет передавать ресурсы объекта новому владельцу вместо их полного копирования. В C++ её поддерживают move-конструктор `T(T&&)` и move-присваивание `T& operator=(T&&)`. `std::move` не перемещает сам: он превращает выражение в xvalue, после чего может выбираться move-операция. Для стандартных типов источник обычно остаётся валидным, но в неуточнённом состоянии. Для своего класса это определяет автор.

[[Семантика перемещения#Что такое семантика перемещения?|Полный ответ]]

### 2. Что такое deep copy и shallow copy?

Shallow copy — копирование без создания независимых копий внешних ресурсов. Если класс хранит сырой указатель, копия получит тот же адрес: изменение ресурса видно через оба объекта, а два `delete` приведут к UB. Deep copy создаёт независимый ресурс и копирует его содержимое: например, `x = new int(*other.x)`. Тогда объекты не разделяют данные. Обычно лучше применять RAII: `std::string`, контейнеры и умные указатели, а не вручную управлять `new`/`delete`.

[[Семантика перемещения#Что такое deep copy и shallow copy?|Полный ответ]]

### 3. Что такое rvalue и lvalue? Какие ещё категории значений ты знаешь?

`lvalue` — выражение с идентичностью объекта: например `x`. `prvalue` — чистое значение без идентичности объекта в выражении: `42`, `x + 1`. `xvalue` — объект с идентичностью, ресурсы которого можно передавать: `std::move(x)` или результат функции `T&&`. `prvalue` и `xvalue` составляют `rvalue`, а `lvalue` и `xvalue` — `glvalue`. Важно: наличие `&&` в типе не делает именованную переменную rvalue — `T&& arg` при использовании `arg` остаётся lvalue.

[[Семантика перемещения#Что такое rvalue и lvalue? Какие ещё категории значений ты знаешь?|Полный ответ]]

### 4. Что делает `std::move`? Как устроен `std::move`?

`std::move` ничего сам не перемещает. Он приводит выражение к xvalue, чтобы следующая операция могла выбрать перемещение.

```cpp
template<class T>
std::remove_reference_t<T>&& move(T&& x) {
    return static_cast<std::remove_reference_t<T>&&>(x);
}
```

`remove_reference_t` убирает ссылку из `T`, чтобы `&&` не свернулось в `&`. Перемещает ресурсы конструктор или оператор присваивания, а `move` лишь разрешает это.

[[Семантика перемещения#Что делает std::move? Как устроен std::move?|Полный ответ]]

### 5. Что делает `std::forward`? Как устроен `std::forward`?

`std::forward<T>(x)` сохраняет исходную категорию аргумента при передаче из шаблона. Именованный `arg` — lvalue, даже если его тип `T&&`.

Упрощённо, одна перегрузка:
```cpp
template<class T>
T&& forward(std::remove_reference_t<T>& x) {
    return static_cast<T&&>(x);
}
```

Если `T = U&`, результат lvalue; если `T = U`, результат xvalue. Использование: `process(std::forward<T>(arg))`. В отличие от `move`, не превращает lvalue-аргумент в xvalue.

## Исключения

### 1. Расскажи, как работает механизм исключений.

`throw` создаёт объект исключения и передаёт управление подходящему `catch` в ближайшем охватывающем `try`. При выходе из вызовов до обработчика раскручивается стек: уничтожаются созданные локальные объекты. Обработчики проверяются по порядку. Если подходящего обработчика нет или исключение выходит из `noexcept`-функции, вызывается `std::terminate`. `throw;` внутри обработчика повторно бросает текущее исключение.

[[Исключения#Расскажи, как работает механизм исключений.|Полный ответ]]

### 2. Когда нужно использовать исключения, а когда коды ошибок?

Коды ошибок удобны, когда результат ожидаем и обрабатывается рядом с вызовом, например «не найдено». В C++23 можно использовать `std::expected<Value, Error>`. Исключения подходят, когда операция не может выполнить контракт, а обработчик находится выше по стеку. Они отделяют обработку ошибки от основной логики и позволяют передать её через несколько уровней вызовов.

[[Исключения#Когда нужно использовать исключения, а когда коды ошибок?|Полный ответ]]

### 3. Расскажи об иерархии расположения catch-блоков

Обработка ошибок должна начинаться с наиболее узкоспециализированных ошибок и идти к наиболее общим: сначала производные типы исключений, затем базовые. Например, `std::runtime_error` перед `std::exception`. Выбирается первый подходящий обработчик. `catch (...)` ловит любое исключение и должен стоять последним. Обычно ловят по `const`-ссылке, чтобы избежать копирования и срезки.

[[Исключения#Расскажи об иерархии расположения catch-блоков|Полный ответ]]

### 4. Можно ли бросать исключение из конструктора? О чем нужно помнить, когда мы бросаем исключения из конструктора?

Из конструктора **можно** бросать исключение, но деструктор недостроенного объекта вызван не будет. Уже полностью созданные поля и базовые подобъекты уничтожаются автоматически. Чтобы избежать утечек, ресурсы должны принадлежать RAII-объектам, например умным указателям. Если конструктор не может создать корректный объект, исключение сообщает об этом вызывающему коду.

[[Исключения#Можно ли бросать исключение из конструктора? О чем нужно помнить, когда мы бросаем исключения из конструктора?|Полный ответ]]

### 5. Можно ли бросать исключение из деструктора?

Формально бросить исключение можно, но выпускать его из деструктора не рекомендуется. Деструктор обычно `noexcept(true)`: выход исключения приводит к `std::terminate`. Можно указать `noexcept(false)`, но выход исключения при раскрутке стека из-за другого исключения всё равно вызовет `std::terminate`. Бросить и перехватить исключение внутри деструктора допустимо.

[[Исключения#Можно ли бросать исключение из деструктора?|Полный ответ]]

### 6. Что произойдет, если dynamic_cast не сможет скастовать тип?

`dynamic_cast` по разному себя ведет с ссылками и указателями. Для ссылок - выбрасывание исключения `std::bad_cast`, а для указателей вернёт `nullptr`

[[Исключения#Что произойдет, если dynamic_cast не сможет скастовать тип?|Полный ответ]]

### 7. Зачем используется ключевое слово `noexcept`?

`noexcept` указывает, что исключение не должно выходить из функции; иначе вызывается `std::terminate`. Внутри функции его можно бросить и перехватить. Помогает выбирать безопасное перемещение: `std::vector` при перераспределении может копировать, если перемещение бросает и копирование доступно. Может помогать оптимизации, но ускорение не гарантировано. Оператор `noexcept(expr)` проверяет потенциальную бросаемость выражения без выполнения.

[[Исключения#Зачем используется ключевое слово noexcept?|Полный ответ]]

### 8. Что произойдет, если при попытке выделить память с помощью new памяти не хватит?

Если обычный `new` не может выделить память, он бросает `std::bad_alloc`. Если исключение не перехвачено, вызывается `std::terminate`. Сам по себе огромный размер запроса не гарантирует отказ: результат зависит от ОС и настроек памяти.

[[Исключения#Что произойдет, если при попытке выделить память с помощью new памяти не хватит?|Полный ответ]]

### 9. Как сделать так, чтобы new не бросал исключение?

Использовать `new (std::nothrow)`: при отказе выделения памяти он возвращает `nullptr`. Результат нужно проверить. Исключения из конструктора эта форма не подавляет.

```cpp
#include <new>
int* p = new (std::nothrow) int[100];
// Проверить p перед использованием.
// После использования: delete[] p;
```

## Идиомы

### 1. Что такое идиома RAII? Напиши код. Приведи примеры RAII в STL.

RAII связывает владение ресурсом со временем жизни объекта: захват при инициализации, освобождение в деструкторе, в том числе при исключении. Примеры: `std::unique_ptr`, `std::vector`, `std::string`, `std::lock_guard`, файловые потоки.

```cpp
#include <memory>
void work() {
    auto p = std::make_unique<int[]>(100);
} // Массив освобождается автоматически
```

[[Идиомы#Что такое идиома RAII? Напиши код. Приведи примеры RAII в STL.|Полный ответ]]

### 2. Что такое RVO? Напиши код.

RVO (Return Value Optimization) устраняет промежуточное копирование или перемещение возвращаемого объекта. Результат создаётся сразу в месте назначения. С C++17 для возврата prvalue того же типа это гарантировано; NRVO остаётся необязательной.

```cpp
struct A {};
A getA() {
    return A();
}
A a = getA();
```

[[Идиомы#Что такое RVO? Напиши код.|Полный ответ]]

### 3. Что такое NRVO? Напиши код.

`NRVO` (`Named Return Value Optimization`) - частный случай `RVO`, связанный с возвратом именнованных локальных объектов из функции.

```C++
A getA() {
  auto x = A();
  return x; // NRVO
}
```

NRVO необязательна даже в C++17 и новее. В примере `A` - класс из предыдущего ответа.

[[Идиомы#Что такое NRVO? Напиши код.|Полный ответ]]

### 4. Что такое SSO?

SSO (Small String Optimization) - оптимизация в реализациях `std::basic_string`: короткие строки хранятся внутри самого объекта, а длинные - в отдельном динамическом буфере. Это позволяет избежать выделения памяти для короткого текста. Сам объект строки может находиться и на стеке, и в куче. SSO и предельная длина короткой строки зависят от реализации и не гарантируются стандартом.

[[Идиомы#Что такое SSO?|Полный ответ]]

### 5. Что такое PIMPL? Напиши код.

PIMPL скрывает детали реализации во вспомогательном классе, оставляя в заголовке указатель на него. Изменения реализации меньше затрагивают клиентский код.

```cpp
// A.h
#include <memory>
class A {
    struct Impl;
    std::unique_ptr<Impl> p;
public:
    A();
    ~A();
};
// A.cpp, после #include "A.h"
struct A::Impl { int x = 0; };
A::A() : p(std::make_unique<Impl>()) {}
A::~A() = default;
```

[[Идиомы#Что такое PIMPL?|Полный ответ]]

### 6. Что такое идиома copy-and-swap (гарантия безопасности при копировании объектов)? Напиши код.

Copy-and-swap: сначала создаётся независимая копия правого операнда, затем состояния обмениваются через `swap`. Временный объект освобождает старый ресурс. Если копирование бросит, левый объект не изменится. При небросающих `swap` и деструкторе обеспечивается сильная гарантия исключений.

```cpp
T& operator=(T other) {
    swap(other);
    return *this;
}
```

[[Идиомы#Что такое идиома copy-and-swap|Полный ответ]]

### 7. Что такое EBO? Напиши код.

EBO (Empty Base Optimization) позволяет не выделять отдельное место под пустой базовый подобъект. Отдельный объект пустого класса занимает минимум 1 байт. Оптимизация ограничена требованиями к различным адресам подобъектов одного типа.

```cpp
struct Base {};
struct Derived1 : Base {
    int i;
};
// Обычно sizeof(Derived1) == sizeof(int).
```

## Разное

### 1. Расскажи, как устроена лямбда

Лямбда — безымянный функциональный объект. Компилятор создаёт уникальный closure-класс с `operator()`. `[]` задаёт захват переменных, `()` — параметры, `{}` — тело, `mutable` снимает const с `operator()` и позволяет менять копии захваченных по значению переменных.

```cpp
int x = 10;
auto next = [x]() mutable { return ++x; };
```

[[Разное#Расскажи, как устроена лямбда|Полный ответ]]

### 2. Сколько памяти занимает пустой класс?

Отдельный объект пустого класса занимает минимум 1 байт. EBO (Empty Base Optimization) позволяет пустому базовому подобъекту не занимать отдельного места.

```cpp
struct Base {};
struct Derived : Base { int i; };
// Обычно sizeof(Derived) == sizeof(int)
```

Размеры зависят от ABI и выравнивания.

### 3. Какие виды кастов в C++ ты знаешь?

Основные cast'ы: `static_cast` — преобразование, проверяемое компилятором; `dynamic_cast` — проверка типов в runtime в полиморфной иерархии; `const_cast` — добавление или снятие const/volatile; `reinterpret_cast` — низкоуровневое преобразование представления; C-style cast `(T)value` — попытка применить несколько видов преобразований, поэтому хуже показывает намерение. Неправильный cast может привести к UB.

### 4. Что такое перегрузка операторов? Какие операторы нельзя перегружать?

Перегрузка операторов задаёт поведение операторов для пользовательских типов через функции `operator+`, `operator==`, `operator[]` и т.д. Нельзя перегрузить `.`, `.*`, `::`, `?:`, а также `#` и `##`. Приоритет, ассоциативность и число операндов изменить нельзя. `co_await` можно перегрузить через `operator co_await`.

### 5. Зачем нужно ключевое слово `friend`? Как он влияет на инкапсуляцию?

`friend` объявляет функцию или класс другом и даёт доступ к `private` и `protected` членам. Друг не становится членом класса, дружба не наследуется и автоматически не является взаимной. Это контролируемое расширение доступа; пример — `operator<<`, которому нужно читать внутренние данные объекта.

## Принципы разработки (KISS, DRY, YAGNI)

### 1. Что такое принцип KISS (Keep It Simple, Stupid)? Приведи пример кода, который его нарушает.

**KISS** (Keep It Simple, Stupid) — принцип выбора простого решения, достаточного для задачи. Не следует добавлять лишние классы и уровни абстракций.

```cpp
// Нарушение KISS для простой суммы:
class Sum { public: int calculate(int a, int b) { return a + b; } };
// Достаточно: int result = a + b;
```

### 2. Что такое принцип DRY (Don't Repeat Yourself)? Какие проблемы возникают при дублировании кода?

**DRY** (Don't Repeat Yourself) — не дублируй знания и правила в коде. Общую логику выносят в одну функцию или компонент. Дублирование приводит к расхождениям: при изменении правила одно из мест можно забыть обновить. Это увеличивает стоимость поддержки, количество ошибок и объём тестирования.

[[Принципы разработки (KISS, DRY, YAGNI)#Что такое принцип DRY (Don't Repeat Yourself)? Какие проблемы возникают при дублировании кода?|Полный ответ]]

### 3. Что такое принцип YAGNI (You Aren't Gonna Need It)? Какие риски несёт добавление функциональности «про запас»?

**YAGNI** (You Aren't Gonna Need It) — реализуй только то, что нужно текущей задаче. Функциональность «про запас» увеличивает сложность, время разработки и тестирования, добавляет код для поддержки и может оказаться ненужной из-за изменения будущих требований.

[[Принципы разработки (KISS, DRY, YAGNI)#Что такое принцип YAGNI (You Aren't Gonna Need It)? Какие риски несёт добавление функциональности «про запас»?|Полный ответ]]

### 4. Могут ли KISS и DRY вступать в противоречие друг с другом? Приведи пример.

KISS и DRY могут конфликтовать. KISS поощряет два понятных похожих метода, а DRY — одну универсальную функцию. Если объединение требует флагов и сложной абстракции, дублирование может быть понятнее. Нужно устранять существенное дублирование, не ухудшая читаемость.
