## Расскажи, как устроена лямбда

**Функциональный объект** - объект класса, в котором опредлён оператор `()`, что позволяет объекту такого типа вызываться как скобочки.

**Функтор** = Функциональный объект

**Лямбда-функция** - это синтаксис для создания безымянного функтора прямо в месте использования. Компилятор создаёт уникальный closure type с `operator()` (https://cppinsights.io/)

**Например:**
```C++
int main() {
  int x;
  auto d = [&x]() { x++; };
  d();
}
// =====
int main()
{
  int x;
    
  class __lambda_6_12
  {
    public: 
    inline constexpr void operator()() const
    {
      x++;
    }
    
    // private: 
    int & x;
  };
  
  __lambda_6_12 d = __lambda_6_12{x};
  d.operator()();
  return 0;
}

```

Лямбда состоит из 3 частей: `[]`; `()`; `{}`
```
[captures](parameters) mutable -> return_type {
    body
};
```
- `[]` - захват переменных из внешней области видимости
- `()` - параметры `operator()`, передаваемые при вызове
- `mutable` - делает `operator()` неконстантным
- `-> return_type` - явный возвращаемый тип, обычно выводится автоматически
- `{}` - тело лямбды

**Мутабельные лямбды**
Проблема функторов, которые создаются в `С++` - они константы, поэтому `[]` вынужден полчать объект по ссылки, так как ссылку можно изменять в константных методах класса. Но как быть, если мы хотим захватить объект по значению и изменить его в лямбда функции. Поможет ключевое слово `mutable`, которое снимает константность с функтора.

```C++
int main() {
  int x = 10;
  auto d = [x](){ x++; };
  d();
}
// =====
int main()
{
  int x = 10;
    
  class __lambda_6_12
  {
    public: 
    inline constexpr void operator()()
    {
      x++;
    }
    
    // private: 
    int x;
  };
  
  __lambda_6_12 d = __lambda_6_12{x};
  d.operator()();
  return 0;
}
```


## Сколько памяти занимает пустой класс?

В `C++` класс не может весить менее 1 байта, это необходимо для того, чтобы разные объектвы одного типа имели разные адреса. Но в `C++` есть оптимизация `EBO` (`Empty Base Optimization`) (https://en.cppreference.com/cpp/language/ebo), которая позволяет не выделять память под пустой класс в базовом классе (Обязательно с `C++11`).

**Например:**
```C++
struct Base {}; // пустой класс
struct Derived1 : Base
{
    int i;
};
// sizeof(Derived1) == sizeof(int) - пустой базовый класс не занимает места
```

`EBO` не работает в двух случаях:
1) Если пустой базовый класс совпадает с **первым** типом члена данных производного класса
```C++
struct Base {};
struct Derived1 : Base {
  Base b;
  int i;
};
// sizeof(Derived1) != sizeof(int) - 8 != 4
```
2) Если **первый** член данных производного класса сам унаследован от базового класса
```C++
struct Base {};
struct Derived1 : Base {
  int x;
};
struct Derived2 : Base {
  Derived1 b; // 4 + 1(4)
  int i;      // 4
};
// = 4 + 4 + 4 = 12
```

Отметим, если в классе есть хотя бы один виртуальный метод или виртуальный деструктор, класс становится полиморфным. Стандарт C++ не предписывает конкретную реализацию виртуального вызова, но большинство ABI используют `vtable` и скрытый указатель `vptr` внутри каждого объекта.


## Какие виды кастов в C++ ты знаешь?

1. `static_cast`
`static_cast` - явное преобразование, которое говорит компилятору, что выражение осознано приводит один тип к другому, если это разрешено правилом языка (пример 1.1).
Возможность выполнения `static_cast` проверяется на этапе компиляции, поэтому никаких исключений или `nullptr` `static_cast` не вызывает, но он вполне может привести к `UB` при неправильном кастовании, как в примере 1.2
**Пример 1.1**
```C++
int x = 10;
auto y = static_cast<float>(x);
```
**Пример 1.2**
```C++
class Animal {
public:
  virtual ~Animal() = default;
};

class Dog : public Animal {
public:
  void bark() {}
};

class Cat : public Animal {};

int main() {
  Animal *animal = new Cat;

  Dog *dog = static_cast<Dog *>(animal);
  dog->bark(); // UB
  return 0;
}
```

`static_cast` поразному работает при `upcast` и `downcast` и для числовых типов
Для числовых типов `static_cast` выполняет операции процессора по преобразованию (Пример 1.1).
При `upcast` и `downcast` `static_cast` лишь на уровне языка изменяет правила работы с объектом (Пример 1.3).
```
class Base {
public:
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    void run() {}
};

class Other : public Base {};

Base* a = new Derived;
Base* b = new Other;

static_cast<Derived*>(a)->run(); // A - Валидный cast, так как a указывает на Base внтри объекта Derived
static_cast<Derived*>(b)->run(); // B - Невалидный cast, так как теперь C++ будет работать с объектом b, как будто бы это Derived, но на деое это Other
```

2. `dinamic_cast`
`dynamic_cast` — это runtime-проверяемый cast для работы с объектами в полиморфной иерархии. Он нужен там, где `static_cast` потребовал бы от программиста внешней гарантии реального типа объекта и при ошибке мог бы привести к Undefined Behavior (UB).

Для runtime-проверяемого downcast или cross-cast исходный тип должен быть **полиморфным** — иметь хотя бы одну `virtual`-функцию. Обычно для этого базовому классу задают виртуальный деструктор.

**Пример 2.1**

```cpp
class Base {
public:
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    void run() {}
};

Base* base = /* объект может быть Derived, Other или nullptr */;
```

`dynamic_cast`

```cpp
Derived* derived = dynamic_cast<Derived*>(base);

if (derived != nullptr) {
    derived->run();
}
```

`dynamic_cast` проверяет реальный тип объекта в runtime. Если `base` действительно указывает на `Derived` или его потомка, `derived` будет корректным указателем. Если объект имеет другой тип или `base == nullptr`, результатом будет `nullptr`.

### `static_cast`

```cpp
Derived* derived = static_cast<Derived*>(base);
derived->run(); // UB, если объект не является Derived
```

`static_cast` проверяет только связь типов на этапе компиляции: например, что `Derived` наследуется от `Base`. Но он не проверяет реальный динамический тип объекта. Если `base` указывает на `Other`, использование результата как `Derived*` приводит к UB.

> В исходном черновике во втором примере был случайно указан `dynamic_cast`; здесь должен быть `static_cast`.

## Указатель и ссылка

`dynamic_cast` имеет разное поведение для указателя и ссылки.

| Форма | Успех | Неуспех |
|---|---|---|
| `dynamic_cast<Derived*>(base_ptr)` | Возвращает корректный `Derived*` | Возвращает `nullptr` |
| `dynamic_cast<Derived&>(base_ref)` | Возвращает корректную `Derived&` | Бросает `std::bad_cast` |

Причина различия: указатель может быть `nullptr`, а корректной «пустой ссылки» в C++ не существует.

```cpp
Base& base_ref = /* ... */;

try {
    Derived& derived = dynamic_cast<Derived&>(base_ref);
    derived.run();
} catch (const std::bad_cast&) {
    // Объект не Derived.
}
```

## `dynamic_cast<void*>`

```cpp
void* whole_object = dynamic_cast<void*>(base_ptr);
```

`dynamic_cast<void*>` — специальный вариант `dynamic_cast`.

Если `base_ptr` указывает на полиморфный объект, результатом будет `void*`, указывающий на начало полного, most-derived объекта, а не обязательно на тот `Base`-подобъект, на который указывал исходный `Base*`.

Это особенно заметно при множественном наследовании: базовый подобъект может располагаться не в начале полного объекта.

## Cross-cast

`dynamic_cast` поддерживает также **cross-cast**: переход между разными полиморфными базовыми интерфейсами через общий полный объект.

### Пример 2.2

```cpp
class Printable {
public:
    virtual ~Printable() = default;
    virtual void print() const = 0;
};

class Serializable {
public:
    virtual ~Serializable() = default;
    virtual void save() const = 0;
};

class Document : public Printable, public Serializable {
public:
    void print() const override {}
    void save() const override {}
};

Document document;

Printable* printable = &document;

Serializable* serializable =
    dynamic_cast<Serializable*>(printable);
```

Здесь `serializable != nullptr`, потому что `printable` указывает на `Printable`-подобъект внутри полного объекта `Document`, а `Document` также содержит `Serializable`-подобъект.

```text
Document
├── Printable      ← printable
└── Serializable   ← serializable
```

`dynamic_cast` во время выполнения определяет реальный тип полного объекта и при необходимости корректирует адрес указателя до `Serializable`-подобъекта. `static_cast<Serializable*>(printable)` здесь не скомпилируется, потому что `Printable` и `Serializable` не находятся в отношении наследования друг с другом.
