


**Создание по умолчанию:** ДА. Компилятор генерирует поверхностное копирование объекта (shallow copy)
**Описание:** Конструктор копирования производит копирование всех полей в новый объект
**Сигнатура:**
```C++
Foo(const Foo &foo);
```
**Примеры:**
Посмотрим на простую реализацию конструктора копирования:
```C++
class Foo {
private:
  int a_;

public:
  Foo(const Foo &foo) { a_ = foo.a_; }
};
```
Конструктор копирования принимает `const &` на объект того же типа и имеет доступ к приватным полям класса. Пример выше немного искусственный, так как нам бы подошла и стандартная реализация конструктора копирования

Рассмотрим более сложный вариант:
```C++
class Foo {
private:
  int *a_;

public:
  Foo(const Foo &foo) : a_(new int{*foo.a_}) {}
};
```
В примере выше (если опустить, что `_a` может принимать форму `nullptr`) мы вынуждены самим реализовывать конструктор копирования, иначе компилятор просто реализует за нас, что-то на подобии `Foo(const Foo &foo) : a_(foo.a_)`


## Реализация компилятором дефолтных правил копирования

Стандарт даёт строго [определение тривиальности](https://ru.cppreference.com/cpp/language/classes)







### Правило трех

**Правило трёх** сформулировал *Скотт Мейерс* в своей книге "Effective C++"
>Если классу необходим один из следующих методов, то скорее всего ему понадобятся и два других: Деструктор, Конструктор копирования, Оператор присваивания копированием


## Разбор кейсов

**Вопрос:** Почему программа падает с ошибкой`free(): double free detected in tcache 2` 
```C++
class Image {
private:
  char *pixels_;

public:
  Image() : pixels_(new char[1024]) {}

  Image(const Image &other) : pixels_(new char[1024]) { // (2)
    std::memcpy(pixels_, other.pixels_, 1024);
  }

  ~Image() { delete[] pixels_; }
};

int main() {
  Image img1;
  Image img2;
  img2 = img1; // (1)
  return 0;
}
```
**Ответ:** Это пример демонстрирующий пренебрижение правилом трёх, мы видим деструктор, конструктор копирования, но нет **оператора присвоения копированием**. Из-за это причины `(1)` не вызывает `(2)`, решить можно при помощи блока `(3)`:
```C++
Image &operator=(const Image &other) { // (3)
	if (this != &other) {
		delete[] pixels_;
		pixels_ = new char[1024];
		std::memcpy(pixels_, other.pixels_, 1024);
	}

	return *this;
}
```

**Вопрос:** Что выведется на экран?
```C++
struct Connection {
  int id = 0;
  Connection() = default;

  Connection(Connection &other) { // (1)
    std::cout << "Connection(Connection &other)" << std::endl;
  }

  Connection(const Connection &other) { // (2)
    std::cout << "Connection(const Connection &other)" << std::endl;
  }
};

int main() {
  const Connection c1;
  Connection c2;
  std::cout << "Result:" << std::endl;
  Connection c3 = c1;
  Connection c4 = c2;
}
```
**Ответ:** На экране будет
```C++
Result:
Connection(const Connection &other)
Connection(Connection &other)
```
Запись формата `Connection(Connection &other)` менее универсальная и не подходит для `const` объектов, но в общем случаи при копировании компилятор выберет именно ее. Поэтому объект `c3` будет вызван  `(2)`, а объекту `c4` будет вызван `(2)`

**Вопрос:** Почему нельзя использовать конструктор копирования без ссылок?
```c++
Connection(Connection other) {
	std::cout << "Connection(const Connection &other)" << std::endl;
}
```

```bash
main.cpp:12:3: error: invalid constructor; you probably meant ‘Connection (const Connection&)’
   12 |   Connection(Connection other) {
      |   ^~~~~~~~~~
```
**Ответ:** Мы получим рекурсию, предположим мы решили выполнить нечто подобное
```C++
Connection c1; // (1)
Connection c2 = c1; // (2)
```
* Для `(1)` нам достаточно обычного конструктора
* При создании `(2)` нам необходимо вызвать конструктор копирования `Connection(Connection other)`, который в свою очередь просит копию объекта `Connection` - бесконечная рекурсия
