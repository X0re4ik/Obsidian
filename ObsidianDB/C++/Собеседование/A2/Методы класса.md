
**Что такое конструктор?**

Особый вид метода класса, который автоматически вызывается при создании объекта класса
Особенности конструктора:
* Название идентично названию класса
* Не имеет возвращаемого значения

**Существует ли виртуальный конструктор?**

Нет! Виртуальных конструкторов быть не может.


**Какие виды конструкторов ты знаешь?**

1) Конструктор по умолчанию
Генерируется компилятором по умолчанию, если контруктор не объявлен, так как у каждого объекта обязан быть конструктор

2) Консруктор с параметрами
Если мы хотим явно создавать объект из опредленных параметров, то используем этот вид контрукторов. Конструкторам с параметрами разрешены перегрузки, поэтому на них распостраняются все правила разрешения перегрузок

3) Конструктор копирования (Copy Constructor)
**Создание по умолчанию:** ДА. Компилятор генерирует поверхностное копирование объекта (shallow copy)
**Описание:** Конструктор копирования производит копирование всех полей в новый объект
**Сигнатура:**
```C++
Foo(const Foo &foo);
```
**Примеры:**
Посмотрим на простую реализацию конструктора копирования:
```C++
class Foo {
private:
  int a_;

public:
  Foo(const Foo &foo) { a_ = foo.a_; }
};
```
Конструктор копирования принимает `const &` на объект того же типа и имеет доступ к приватным полям класса. Пример выше немного искусственный, так как нам бы подошла и стандартная реализация конструктора копирования

Рассмотрим более сложный вариант:
```C++
class Foo {
private:
  int *a_;

public:
  Foo(const Foo &foo) : a_(new int{*foo.a_}) {}
};
```
В примере выше (если опустить, что `_a` может принимать форму `nullptr`) мы вынуждены самим реализовывать конструктор копирования, иначе компилятор просто реализует за нас, что-то на подобии `Foo(const Foo &foo) : a_(foo.a_)`

**Что такое список инициализации (member initializer list)? Почему некоторые поля обязательно нужно инициализировать через него (например, ссылки, const-поля)?**

Чтобы понять роль `member initializer list` необходимо чуть глубже изучить вопрос создания объекта в `C++`. Рассмотрим простой класс `Point`:

**Пример:**
```C++
class Point {
public:
  int x_;
  int y_;
  Point(int x, int y) {
    std::cout << "x=" << x_ << ";y=" << y_ << std::endl; // (1)
    x_ = x;
    y_ = y;
  }
};

int main(int, char **) {
  Point{1, 2};
  return 0;
}
```

Создание объекта в C++ присходит строго сверху-внизу, то есть в случаи класса `Point` сначала создасться `x_`, а только после `y_`. Но в момент `(1)` они уже будут проинициализированы и созданы, то есть строка `(1)` выведент на экран мусор.
Необходим механизм, который бы инициализировал объекты внутри класса **до** создание самого класса - `member initializer list`.

**Пример:**
```C++
class Point {
public:
  int x_; // (3)
  int y_; // (4)
  Point(int x, int y): x_{x}, y_{y} { // (2)
    std::cout << "x=" << x_ << ";y=" << y_ << std::endl;
  }
};
```

Теперь объекты `(3)` и `(4)` будут созданы в момент создания класса Point и проинициализированы полями из строки `(2)`. Но `member initializer list` не решает проблему порядка инициализации объектов. Рассмотрим пример:

```C++
struct X {
  X() { std::cout << "X" << std::endl; }
};

struct Y {
  Y() { std::cout << "Y" << std::endl; }
};

class Point {
public:
  X x_;
  Y y_;
  Point(X x, Y y) : y_{y}, x_{x} {}
};

int main(int, char **) {
  Point{{}, {}};
  return 0;
}
```

Скомпилируем программу и выполним

```bash
>> g++ main.cpp -o main -Wall
main.cpp: In constructor ‘Point::Point(X, Y)’:
main.cpp:18:5: warning: ‘Point::y_’ will be initialized after [-Wreorder]
   18 |   Y y_;
      |     ^~
main.cpp:17:5: warning:   ‘X Point::x_’ [-Wreorder]
   17 |   X x_;
      |     ^~
main.cpp:19:3: warning:   when initialized here [-Wreorder]
   19 |   Point(X x, Y y) : y_{y}, x_{x} {}
      |   ^~~~~
>> ./main
X
Y
```

Мы видим, что объекты `x_` и `y_` были созданы согласно порядку опредления в классе, а нарушение порядка определения в  `member initializer list` привело к предупреждения.

Описание выше наглядно показывает почему для объектов `const` и ссылок их инициализация обязательно в `member initializer list`.
* `const` - В момент входа в тело конструктора объект **уже** будет создан и изменять его значение из-за константонсти нельяза
* ссылки - В момент входа в тело конструктора ссылка не сможет создасться, так как ей просто не на что ссылаться

```C++
class Point {
public:
  X &x_;
  const Y y_;
  Point(X &x, Y y) {
    x_ = x; // (1) Невозможо создать ссылку, которая ни на что не ссылается
    y_ = y; // (2) Невозможно изменять объект, который const
  }
};
```

Влияние на перфоманс, в теле контруктора мы выполняем операцию **присвоения**, а в списке инициализации - **инициализацию**, так например в примере мы сначала создаём объект `X`, а потом еще раз создаём объект `X`, чтобы выполнить присвоение.
