Особенности конструктора:
* Название идентично названию класса
* Не имеет возвращаемого значения

**Существует ли виртуальный конструктор?**

Нет! Виртуальных конструкторов быть не может.


**Какие виды конструкторов ты знаешь?**

1) Конструктор по умолчанию
Генерируется компилятором по умолчанию, если контруктор не объявлен, так как у каждого объекта обязан быть конструктор

2) Консруктор с параметрами
Если мы хотим явно создавать объект из опредленных параметров, то используем этот вид контрукторов. Конструкторам с параметрами разрешены перегрузки, поэтому на них распостраняются все правила разрешения перегрузок

3) Конструктор копирования (Copy Constructor)
**Создание по умолчанию:** ДА. Компилятор генерирует поверхностное копирование объекта (shallow copy)
**Описание:** Конструктор копирования производит копирование всех полей в новый объект
**Сигнатура:**
```C++
Foo(const Foo &foo);
```
**Примеры:**
Посмотрим на простую реализацию конструктора копирования:
```C++
class Foo {
private:
  int a_;

public:
  Foo(const Foo &foo) { a_ = foo.a_; }
};
```
Конструктор копирования принимает `const &` на объект того же типа и имеет доступ к приватным полям класса. Пример выше немного искусственный, так как нам бы подошла и стандартная реализация конструктора копирования

Рассмотрим более сложный вариант:
```C++
class Foo {
private:
  int *a_;

public:
  Foo(const Foo &foo) : a_(new int{*foo.a_}) {}
};
```
В примере выше (если опустить, что `_a` может принимать форму `nullptr`) мы вынуждены самим реализовывать конструктор копирования, иначе компилятор просто реализует за нас, что-то на подобии `Foo(const Foo &foo) : a_(foo.a_)`

4) Конструктор перемещения
5) Делегирующий конструктор

### 8. Что такое виртуальная функция?

Виртуальная функция — это функция-член, которую предполагается переопределить в производных классах. Отличительная черта виртуальных функций — наличие ключевого слова `virtual`.

Чтобы наглядно рассмотреть роль `virtual`, рассмотрим следующий пример:

```cpp
#include <iostream>

class Base {
public:
  virtual void NameOf() { std::cout << "Base: NameOf" << std::endl; }
  void InvokingClass() { std::cout << "Base: InvokingClass" << std::endl; }
};

class Derived : public Base {
public:
  void NameOf() override { std::cout << "Derived: NameOf" << std::endl; }
  void InvokingClass() { std::cout << "Derived: InvokingClass" << std::endl; }
};

int main() {
  Derived aDerived;
  Base *pBase = &aDerived;
  pBase->InvokingClass(); // (2)
  pBase->NameOf();        // (3)
  return 0;
}
```

Пример выше выведет следующее значение:
```text
Base: InvokingClass
Derived: NameOf
```

Здесь наглядно продемонстрировано правило работы вызова виртуальных и невиртуальных функций:
* Вызов виртуальной функции разрешается в соответствии с динамическим (то есть фактическим) типом объекта, для которого она вызывается.
* Вызов невиртуальной функции разрешается в соответствии с типом указателя или ссылки (статическим типом).

Механизм виртуальных функций можно "подавить" при помощи явного указания базового класса и оператора разрешения видимости (`::`).
Например:

```cpp
int main() {
  Derived aDerived;
  Derived *pDerived = &aDerived;
  pDerived->Base::NameOf();
  return 0;
}
```

Начиная с C++11 появилось ключевое слово `override`, которое позволяет явно сказать компилятору, что эта функция переопределяет виртуальную функцию родителя. Это позволяет нам избавиться от ошибок, когда вместо переопределения мы случайно создали новый метод с чуть иными параметрами.

```cpp
class Base {
public:
  virtual void NameOf() { std::cout << "Base: NameOf" << std::endl; }
};

class Derived : public Base {
public:
  void NameOf() override { std::cout << "Derived: NameOf" << std::endl; }
};
```

У виртуальных функций есть еще одна возможность: они способны превращать классы в абстрактные. Если хотя бы 1 виртуальная функция объявлена как **чистая виртуальная функция** (при помощи `= 0`), то весь класс является абстрактным. Создать экземпляр (объект) абстрактного класса невозможно.

```cpp
class Base { // Абстрактный класс
public:
  virtual void NameOf() = 0; // Чистая виртуальная функция
};
```

### 9. Что такое vtable?

В C++ динамическое связывание (полиморфизм) реализовано при помощи виртуальной таблицы (**vtable**).

**vtable** — это статический массив указателей на виртуальные функции, который создается компилятором на этапе компиляции в единственном экземпляре для каждого класса. Обычно эта таблица хранится в read-only памяти (например, в сегменте `.rodata`).

Для того чтобы объекты знали, к какой таблице обращаться, компилятор неявно добавляет внутрь каждого объекта полиморфного класса специальный указатель на эту таблицу — **vpointer (vptr)**. Это можно легко заметить, сравнив размеры объектов классов с виртуальными методами и без них.

```cpp
#include <iostream>

class Base {
public:
  virtual void NameOf() {}
};

class NotVirtualBase {
public:
  void NameOf() {}
};

int main() {
  std::cout << "Base: " << sizeof(Base) 
            << "\nNotVirtualBase: " << sizeof(NotVirtualBase) << std::endl;
  return 0;
}
```

**Вывод (на x64 архитектуре):**
```text
Base: 8
NotVirtualBase: 1
```

Базовый класс содержит те самые 8 байт, которые весит указатель (`vptr`) на 64-битной машине. Пустой класс `NotVirtualBase` весит 1 байт (минимально возможный размер объекта в C++ для обеспечения уникальности адресов).

#### Множественное наследование
При множественном наследовании объект содержит столько указателей `vptr`, сколько базовых классов с виртуальными методами он наследует. Соответственно, для такого класса компилятор генерирует несколько виртуальных таблиц (или одну сложную таблицу с несколькими точками входа).

Рассмотрим процесс выделения памяти и вызовов на примере множественного наследования:

```cpp
class Base1 {
public:
  virtual void base_1() {}
  virtual void f() {}
};

class Base2 {
public:
  virtual void base_2() {}
  virtual void f() {}
};

class Children : public Base1, public Base2 {
public:
  int x;
};

int main() {
  Children* c = new Children();
  
  c->base_1(); // (1)
  c->base_2(); // (2)

  Base2* b2 = static_cast<Base2*>(c); // (3)
  b2->base_2(); // (4)

  // c->f(); // (5) - Ошибка компиляции
  
  return 0;
}
```

Разберем, что происходит в каждом из отмеченных случаев:

1. `c->base_1();` — Компилятор знает, что подобъект `Base1` находится в начале объекта `Children` (со смещением 0). Происходит обращение к первой vtable и вызов `base_1`. Здесь всё просто.
2. `c->base_2();` — Компилятор знает, что подобъект `Base2` располагается со смещением (обычно 8 байт, сразу после `Base1`). Компилятор неявно корректирует (сдвигает) указатель `this`, чтобы передать в метод `base_2` правильный адрес.
3. `Base2* b2 = static_cast<Base2*>(c);` — Здесь происходит явное приведение типов (upcast). Физически сам объект в памяти не меняется, но **численное значение указателя `b2` сдвигается** (увеличивается на размер `Base1`), чтобы `b2` указывал строго на начало подобъекта `Base2` внутри `Children`. Это называется *pointer adjustment*.
4. `b2->base_2();` — Вызываем метод через указатель на `Base2`. Так как `b2` уже указывает на правильное смещение, метод отрабатывает корректно.
5. `c->f();` — **Ошибка компиляции (ambiguous call)**. Оба родительских класса имеют виртуальный метод `f()`. C++ не знает, какую реализацию выбрать по умолчанию. Эту проблему (неоднозначность) можно решить двумя способами: либо явно указать класс (`c->Base1::f();`), либо переопределить метод `f()` внутри класса `Children`.

### Зачем используется ключевое слово `virtual`?

Ключевое слово `virtual` создает виртуальный метод, которомк свойсвтенны все те свойства и призаки описанные в главе "Что такое виртуальная функция?"

### Зачем используется ключевое слово `final`?

Ключевое слово `final` указывает, что виртуальная функция не может быть переопределена в производном классе или что класс не может наследоваться.

**Пример с виртуальной функцией**

```C++
class Base1 {
public:
  virtual void base_1() {}
};

class Children1 : public Base1 {
public:
  void base_1() override final {}
};

class Children2 : public Children1 {
public:
  void base_1() override {
  } // Ошибка, так как в Children1 метод base_1 помечен как final
};
```

**Пример с классом**

```C++
class Base1 {
public:
  virtual void base_1() {}
};

class Children1 final : public Base1 {
public:
  void base_1() override {}
};

class Children2 : public Children1 {
}; // Ошибка компиляции, Children1 помечен как final, дальнейшее наследование
   // невозможно
```

### Что такое чистая виртуальная функция?

Чистая виртуальная функция - это метод, который не имеет реализации и заканчивается `=0`

**Пример:**
```C++
class Base1 {
public:
  // Чисто виртуальная функция
  virtual void base_1() = 0;
};
```


### Как получить ошибку `pure virtual call`?

Ошибка `pure virtual call` связана с тем, что мы вызываем чисто виртуальную функцию из конструктора или деструктора.
Как получить подобную ошибку: необходимо в контрукторе или деструкторе базового класса вызвать виртуальную функию

**Например**
```C++
class Base {
public:
  Base() { reallyDoIt(); }
  void reallyDoIt() { doIt(); } // DON'T DO THIS
  virtual void doIt() = 0;
};

class Derived : public Base {
  void doIt() {}
};

int main(void) {
  Derived d; // This will cause "pure virtual function call" error
}
```

Почему это приводит к `pure virtual function call`? В момент создания объекта `Derived` происходит создание объекта `Base`, которое состоит в том числе и из вызова цепочки методов `reallyDoIt -> doIt`. В момент создания объекта `Base` программа ничего не знает о классе `Derived` и его переопредленном методе, из-за этого вызывается виртуальный `doIt` и ошибка `pure virtual call`.

Стоит отметить, что компилятор откровенные "ляпы" умеет отлавливать.

**Например**
```C++
class Base {
public:
  Base() { doIt(); }
  virtual void doIt() = 0;
};
```
```bash
>> g++ main.cpp -o main
main.cpp: In constructor ‘Base::Base()’:
main.cpp:5:16: warning: pure virtual ‘virtual void Base::doIt()’ called from constructor
    5 |   Base() { doIt(); }
      |            ~~~~^~
/usr/bin/ld: /tmp/cc2ZQJys.o: в функции «Base::Base()»:
main.cpp:(.text._ZN4BaseC2Ev[_ZN4BaseC5Ev]+0x26): неопределённая ссылка на «Base::doIt()»
collect2: error: ld returned 1 exit status
```

Но если вызов спрятан под обычным методом, то неменуемый `pure virtual call`

Рассмотрим аналогичный пример в деструкторе

**Пример**
```C++
class Base {
public:
  void reallyDoIt() { doIt(); }
  virtual void doIt() = 0;
  virtual ~Base() {
    std::cout << "~Base()" << std::endl;
    reallyDoIt(); // (1)
  }
};

class Derived : public Base {
public:
  void doIt() {}
  ~Derived() { std::cout << "~Derived()" << std::endl; }
};
```

Ситуация аналогичная с конструктором только в противоположном смысле. В момент времени, когда вызывается `(1)` - объект `Derived` уже уничтожен и его переопредленный момент `doIt` не виден, как результат - `pure virtual call`.

### Что такое деструктор?

Деструктор - специальный метод класса, который служит для деинициализации объект (разрушению объекта). Вызов деструктора - последний этап жизненного цикла объекта.

Порядок разрушение объекта:
1) Вызов тела деструктора
2) Разрушение объектов (Вызов деструктора) объектов класса в порядке обратном их объявлению

**Роль исключений в деструктора в `C++11`**

Начиная с `C++11` исключение в деструкторе вызовет мгновенное падение программы с ошибкой `std::terminate`

**Например**
